# 外部 MCP 代码索引审查与修正（2026-10-09）

本轮范围为 `khaslana mcp` 的 stdio 入口、消息与参数验证、仓库路由、后台刷新、跨进程写入及查询统计一致性。延续同日索引审查的未提交改动，不包含第三方客户端 UI 或 HTTP 传输实现。

## 已确认并修正的问题

| 优先级 | 原行为及影响 | 修正 |
| --- | --- | --- |
| P1 | `refresh_index` 无限等待索引任务，串行 stdio 分发无法处理后续 ping 或请求 | 后台任务最多等待 100 毫秒；未完成返回 indexing，由 index_status 轮询。本进程已有任务时增量复用，全量明确拒绝并提示稍后重试 |
| P1 | 只有进程内互斥，GUI 与多个独立 MCP 进程可能基于旧状态同时建库 | 工作区索引和提交快照共用系统文件锁，从扫描前持有到任务退出；竞争者快速失败，保留旧索引可读 |
| P1 | 换行消息先无界分配再检查大小；错误长度头后正文可能作为新请求处理 | 有界读取，单帧 10 MiB、长度帧头部 16 KiB；错误或不完整帧终止连接，不继续执行正文 |
| P2 | 非 UTF-8 字节被替换后继续处理；输出断开仍可能继续消费请求 | 严格 UTF-8，解析失败返回 -32700；输出写入或 flush 失败立即停止分发 |
| P2 | 错类型参数被当作缺省值，数字 repo 可能误选默认仓库；无效消息被当通知忽略 | 按工具 schema 校验必填项、类型、枚举、范围和数组元素，再进行路由和自动刷新；参数错误返回 -32602，无效请求返回 -32600，解析错误 id 为 null |
| P2 | `.git` 路径与工作区根生成不同仓库身份；裸库可能被当工作区扫描 | 通过 Git workdir 规范化根路径；裸仓库明确报错 |
| P2 | 每次按仓库键路由都读取全库统计，并吞掉数据库错误 | 仅查询 repo_path 元数据，数据库错误显式返回；工具 schema 仅初始化一次 |
| P2 | 统计的多次查询可能读取不同提交代际；影响分析未检查代际 | 统计使用同一 SQLite 读取事务；detect_changes 加入 generation 守卫，代际读取失败不再静默忽略 |

同时间索引的项目列表增加仓库键排序，避免顺序不稳定。初始化指引、工具说明和[使用文档](code-index-search.md)同步更新刷新返回契约。

## 证据与边界

按 Tier 2 使用结构图定位、调用关系和源码验证。覆盖检查代际为 `2026-10-09T08:20:51Z`，本轮涉及文件均提示 metadata_changed，因此结论依据直接读取的当前源码与回归测试；未将无缺口记录当作完整性证明。

协议依据：[MCP stdio 传输](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)、[MCP 工具错误处理](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)、[JSON-RPC 2.0](https://www.jsonrpc.org/specification)。Content-Length 是保留的兼容方式，标准 MCP stdio 使用换行 JSON。

尚未实测 Claude Code、Cursor 等第三方客户端的界面连接。stdio 仍串行执行查询，本轮消除了刷新任务的无限等待，没有引入通用并行请求或客户端取消协议。index_status 的任务状态属于当前进程，不是跨进程任务进度；系统锁只协调采用该实现的写入方，不协调旧版本或外部手动修改数据库。解析和调用关系仍是尽力结果，不是完整语义分析。
