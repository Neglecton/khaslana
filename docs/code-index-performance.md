# 大仓库代码索引优化

## 已实现的调整

- 调用点保存在文件级类型结构和独立的二进制暂存表中，不再写入 File 节点的大段 JSON。二进制记录使用文件内字符串字典；导入表每个文件只保存一份。
- 文件路径与限定名使用共享字符串，节点和边的属性使用紧凑字符串。AST 提取结果分批合并并释放，落盘前释放构图去重索引。
- AST 提取和调用解析使用所有仓库共用的计算池，按可用核心数分配工作线程，并限制解析并发的内存预算。文件任务先处理大文件，调用解析按文件并行；文件内缓存包含名字、完整调用表达式和作用域，也缓存未解析结果。
- 后台索引池支持两个任务。不同数据库可并行，同库写入保持互斥；跨入口撞写返回正在索引提示，避免 Rayon 等待期间重入导致挂起。已完成的提交快照直接只读复用，不进入后台建库队列。
- 增量更新通过调用名字反查表定位受定义变化影响的文件，只加载这些文件的调用记录；无关 CALLS 边留在数据库。持久化仅替换变更文件和受影响调用关系，保持其他节点的数据库编号和 FTS 记录。
- 全量节点、关系和调用名字采用有界批量写入。每个写库连接的 SQLite 页缓存上限设为 32MiB；保留 WAL、事务与取消回滚。不修改已有数据库的页大小，也不触发 VACUUM。
- 目录扫描并行执行，保留忽略规则、子仓库剪枝、覆盖记录、文件上限和确定性排序。
- 符号详情、调用链、影响分析和架构统计直接在只读事务中按需查询 SQLite，不再依赖 64MiB 整图缓存。全文搜索继续使用 FTS。

## 兼容与验证范围

数据库 schema 升级到 v4。v2/v3 索引仍可只读查询，打开写库时原位补建暂存表；第一次刷新会全量补建新的调用记录，此后使用增量路径。取消和写入失败保留上一代有效图、全文索引、文件元数据和调用记录。

回归测试覆盖跨文件调用重连、唯一符号变歧义、作用域隔离、未修改行保护、全文索引同步、事务失败回滚、旧库迁移、局部查询和批量写入尾批。按用户要求未访问另一台电脑上的大型仓库，也未做该规模的性能复现。

全量构图仍需保存最终节点、关系和文件级调用暂存；大范围调用链的耗时随实际可达节点数增长。这次修正移除了已确认的重复计算和整库读写放大，具体加速倍数、峰值内存和完成时间仍需在实际大型仓库上测量。
