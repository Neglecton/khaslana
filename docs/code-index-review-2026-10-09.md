# 代码索引审查与优化（2026-10-09）

## 审查范围与依据

本次重点检查工作区文件发现、全量/增量管线、图结构与事务存储、桌面索引任务及统计回填；同时核对 MCP 和提交快照如何复用这些入口。采用 Tier 2 图查询与源码复核，图覆盖检查提示文件元数据变化的部分均回读当前源码。不是全部语言语义、所有 UI 交互或跨进程并发的穷尽审计。

## 已修正的问题

| 优先级 | 触发条件与原行为 | 修正 |
| --- | --- | --- |
| P1 | 仓库目录不存在或遍历失败时，将不完整发现结果作为成功提交，可能清空旧索引 | 扫描前检查目录可读性，遍历错误直接失败，保留上一代索引 |
| P1 | 取消后重启同仓库，旧进度、成功或失败事件仅按仓库键匹配，可能清除新任务或覆盖状态栏 | 事件携带任务编号，仓库和任务身份同时匹配才回填；索引 panic 通过同一身份失败事件收尾 |
| P2 | 统计查询乱序，或删除索引后旧统计回填，页面可能重新显示旧数据 | 按仓库维护最新统计请求编号，消费结果、开始新任务和删除数据时使旧请求失效 |
| P2 | 深层目录没有直接文件时缺失中间目录；增量删除/移动文件后残留空目录和旧分支 | 构建完整祖先链，清理失效目录及分支，并在增量事务内同步删除对应数据库与全文索引记录 |
| P2 | 切换到相同文件内容的另一分支，增量检查直接返回无变化 | 单独检测分支元数据，仅更新结构与元信息，保留未改文件节点和符号 |
| P2 | 文件在扫描后变大，读取和解析仅依赖扫描时大小，可能突破单文件预算 | 读取最多解析上限加一字节，并在解析入口再次检查真实字节数 |

最初新增的四项测试在旧实现上全部失败，分别复现父目录缺失、增量结构残留、仅切分支不刷新、失效仓库路径被当作成功。修正后通过。

## 开销与兼容

- 增量更新只构造变更文件的元数据写入列表，省去复制和排序全仓库未改文件的步骤。
- 目录链先用集合去重，重复路径遇到已收集父目录即停止，不再构造未使用的目录编号表。
- 未改文件及调用关系继续沿用已有增量事务语义；触发器回归测试保护未改文件行，仅切分支的测试也禁止删除或更新文件节点。
- schema 仍为 v4，内容版本调整为 v5。旧库继续可读，下一次刷新事务重建一次以修复旧目录结构；提交快照在下次使用时补建。取消升级保留旧内容版本和代际。
- 更新了搜索文档中已过时的整图缓存描述。
