## 已确认的边界

1. 基于已有代码索引继续演进，做纯代码理解与代码逻辑可视化。
2. 用户用自然语言了解项目、找到业务入口、跟随业务逻辑并核对源码证据。
3. 不加入 Git 融合。提交、分支、diff、blame、作者、变更影响均不作为本功能的输入或图层。
4. **普通 Java 与 Spring Boot 同等列入首版必交付范围**，用户明确接受更大的首版范围。不能把其中一项推迟后仍宣称首版完成。
5. 先实现并验证底层能力，再接入符合项目风格的简约原生桌面入口。
6. 当前任务是三类文档定型；UI 文档规定信息架构和交互，尚未进行高保真画稿、截图 QA 或视觉方案选择。

## 本基线的设计决策

采用“本地代码事实 + 有限范围图查询 + AI 检索与解释 + 源码证据联动”的方案。第一版不要求运行 Java 构建、不自动下载 JDK、不启动语言服务器、不建立向量数据库。Java 的类型与框架适配在本地静态分析层实现；运行时无法确定的关系必须保留候选和原因。

这些是本轮形成的实施基线，并非声称用户逐项确认了技术选型。新增外部服务、JDT LS 强依赖、Git 输入、跨仓库链路或完整运行时分析时，必须先更新需求和设计，不能作为隐含实现细节加入。
