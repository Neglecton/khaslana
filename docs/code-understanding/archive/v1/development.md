代码改动只限本功能必要接入点；不混入 Git 新功能、全仓库格式化、无关重构或依赖大版本升级。新模块按实际需要创建，测试依照现有 `src/tests/` 外移规范组织。

## 4. 接入注意事项

### 4.1 索引存储与查询

- 外部 ID 不可复用 NodeId；运行时 HashMap 下标仅允许在一次 GraphBuffer 内使用。
- 增加 schema 版本时同时检查读库、建库、MCP 查询和设置统计路径。不能只改版本常量而让历史空 sha256 继续被当有效数据。
- 新旧读接口共存期，旧查询通过同事务发布的兼容投影读取。旧 MCP 工具名称保持，新增字段应可选；需要不兼容结构的新查询使用新工具名或显式协议版本。
- 保存原始事实后，删除/修改实现、Bean、import、资源 XML 都应触发关系重新求解。旧边快照只可用于旧格式兼容，不可跳过新语义计算。
- GUI 与 MCP 索引触发必须走同一个“基准代际 → 提取 → 写事务比较 → 发布”协议；仅 GUI Option 状态或 Index 单线程池不足以跨进程互斥。
- Contentless FTS 更新规则容易出错；新 search_documents + FTS 的删除、更新、整库重建必须与数据同事务并有回归。

### 4.2 AI 与事件

- 复用传输和错误处理，不复制现有 review agent 的 Git 工具、落盘或后台完成 toast 路径。
- 新 agent 工具注册表独立、编译期可枚举。mock 测试断言没有 Git/执行类工具；源码中的提示注入无法增加工具。
- 为同项目/全局共享在途限制提供 permit，不能仅判断 Ai 线程池数（线程池排队也会占用内存和用户会话）。
- `AnswerDocument` 修复请求、收尾请求都计入同一轮次/HTTP 预算。临近总轮数时优先预留一次无 tools 收尾；不允许格式修复绕开限额。
- 流式失败重试重置当前尝试的临时文本，不重复执行已落定工具调用；保留已验证工具结果与稳定 ID。
- 读取取消标志的网络粒度需要在真实 ChatClient 上验证；做不到即时 abort 时按设计显示“正在停止”，不能提前释放占用许可而让实际并发超过上限。
- 模型配置/预算报错、源文件变化、取消和结果校验失败分开处理；空正文和仅返回思考过程不算答案。

### 4.3 UI 与兼容

- 新模式按 per-tab 保存输入、选中、导航栈、图视口和源码滚动；切换项目不能借用旧全局输入状态。
- SourceReader 读的是项目文件，不通过 `GitService::blame_file` 或 `browse_file_content`。可复用 syntax 高亮和虚拟列表渲染 helper，不复用 Git 数据源。
- 当前 Markdown 渲染器会把链接降为文本；不要假设已有 Markdown 文本支持引用点击。优先将 `claims/steps/evidence_ids` 渲染为结构化块和来源按钮，仅复用行内文字样式。
- UI 中的图是通过服务 GraphSlice 投影，模型输出 ID 不存在时必须拒绝；禁止直接执行模型生成 Mermaid/HTML/SVG。
- 按 AGENTS.md 的统一键盘、滚动、虚拟列表、ElementId、分隔条和主题 token 规则实现。
- 壳层 Git 按钮不为本功能做无关重排；代码理解只在自己的内容域内移除 Git 语义。

## 6. AI 验证方法

### 6.1 可复现的传输与状态测试

使用现有 AI 客户端测试风格的本地 mock HTTP/SSE，固定脚本覆盖：工具分片、`data:` 无空格、多工具同轮、重试前正文复位、408/429/5xx、400/404/422 配置失败、`finish_reason=length`、EOF 无 DONE、纯思考/空内容、未知工具、预算收尾与格式修复。

断言请求只包含本次项目、允许字段与验证后的证据；用户长输入/历史/工具 schema 也计入上下文预算。测轮数、工具数、结果字符、估算 token、HTTP 尝试四类限制，不能只测 happy path。

### 6.2 真实模型评估

普通 Java 与 Spring 各至少 20 题：每套至少 8 题中文业务定位、4 题调用解释、4 题类型/重载或注入边界、4 题未知/缺失边界。题库冻结后使用同一供应商、模型、提示版本和索引版本运行 3 次，分别报告每次和平均值，不挑最好一次。

- 检索入口 Recall@5：答案前 5 个候选包含人工标注的有效入口。
- 关系 precision/recall：使用静态 fixture 标注独立评估，不用模型评分替代。
- 引用有效率：ID 存在、文件 hash 匹配、范围有效，必须 100%。
- claim 支持度：人工逐条标 supported/partially_supported/unsupported；关键业务结论不得有 unsupported，partial 必须在界面呈现不确定性。
- 歧义安全性：有多个可行实现或未知运行条件时不得宣称唯一执行链。
- 拒答质量：无证据时给范围和可继续动作，不编造项目行为。

真实模型不可用时可以完成确定性测试，但必须记录 CU-04/06 的真实模型验收未完成，不能用 mock 结果冒充实际语义质量。

## 7. 性能与图验证

性能资料建议存 `docs/code-understanding/validation/`，由实现阶段新增，记录版本、硬件、数据集生成种子、节点/边/调用点数量、命令与原始结果摘要。禁止把只有 100 个函数的 demo 成绩填入标准集指标。

1. 生成标准集（10K 文件/100K 符号/500K 聚合关系）及 50K 文件压力集；包含高扇出、孤点、长链、环、跨模块重复名称和 XML 资源。
2. 分别测试冷启动、热查询、全量、1% 文件变化以及只变语义目标的增量；至少 100 次固定查询记录 p50/p95/max。
3. 计入关系全量重算、内容哈希、FTS 更新、数据库发布的时间；不可只报 parse pass。
4. 布局针对 40/80 和 120/240 两档，测试不同输入顺序归一化后的坐标稳定、节点不重叠、边端点落在正确节点、SCC 展开不越限。
5. 峰值内存包括索引中间事实和 GraphBuffer；UI 图缓存设上限（建议最多 8 个 GraphSlice/布局），不得随导航无限增长。
6. 未达需求文档指标时附 flamegraph/计时分段等实际定位证据，优先减少全表查询/重复提取；不能偷偷修改指标或 Java 范围。
