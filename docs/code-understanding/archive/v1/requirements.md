# 代码理解与逻辑可视化需求文档

版本：1.0。状态：需求定型基线，待实现。日期：2026-09-06。

本文定义产品范围与验收；实现机制见[设计文档](design.md)，任务拆分见[开发文档](development.md)。

## 1. 产品目标

在 Khaslana 内增加“代码理解”工作台，让接手陌生项目的开发者通过一句自然语言问题，定位相关模块和业务入口，沿调用关系理解关键处理步骤，并随时查看支持结论的源码。

最小完整闭环是：**提问 → 找到候选入口 → 阅读带证据的解释 → 浏览局部关系图 → 点击源码核对 → 继续追问**。图的作用是帮助定位和理解关系；不能仅交付全仓库节点云或没有源码依据的 AI 聊天。

## 2. 用户与核心问题

| 场景 | 用户的问题 | 期望结果 |
| --- | --- | --- |
| 新人接手 | “这个项目做什么？核心模块在哪里？” | 可核对的模块概览、入口、主要依赖；无法从代码确认的产品背景明确缺失 |
| 业务定位 | “订单取消后在哪里释放库存？” | 若干候选入口、匹配依据、从取消处理到库存逻辑的局部链路 |
| 普通 Java | “这个接口有哪些实现，调用时可能进入哪个？” | 声明类型、实现关系、调用点、候选分派和无法确定的原因 |
| Spring Boot | “这个接口请求最后在哪里落库？” | 路由声明、处理方法、服务调用、Mapper/Repository 边界与源码 |
| 深入阅读 | “校验失败之后会发生什么？” | 方法体中的条件、异常或返回位置及行号，不编造运行时执行轨迹 |
| 持续探索 | “只看库存模块”“继续看这个服务的调用方” | 在明确范围内收缩或展开结果，保留导航上下文 |

示例问题是验收题型，不代表当前 Khaslana 仓库存在订单业务。

## 3. 范围与分期

### 3.1 首版必交付

- 当前已打开项目的本地源文件索引、模块概览、符号搜索、调用/继承/实现关系、源码定位。
- 基于已有 AI 供应商配置的自然语言问答；问题、解释、图与引用相互关联。
- 普通 Java 和 Spring Boot 两条完整验收路线，优先级相同，细目见 §6。
- 项目概览图、以符号为中心的局部关系图、由真实关系组成的业务链路视图。
- 实际调用点证据、候选关系标注、未解析边界、结果截断、索引新鲜度与失败恢复。
- 原生 GPUI 页面、项目间状态隔离、取消、会话内历史导航、深浅主题和窄窗口适配。
- 无 AI 时仍能本地检索符号、查看概览、展开关系和阅读源码。

### 3.2 明确排除

| 排除项 | 边界 |
| --- | --- |
| Git 融合 | 不读取提交、分支、diff、blame、作者、提交频次；不使用现有 `detect_changes` 工具 |
| 运行时追踪 | 不启动应用、附加调试器、采集日志/APM、读取生产数据库或记录真实请求时序 |
| 完整编译器分析 | 不承诺所有重载、泛型、反射、动态代理、AOP、运行时 Bean 条件均可确定；固定样例中的 Java 语言重载按编译期语义判定 |
| 全仓库自动讲解 | 不默认发送整个仓库给模型，不后台逐符号生成摘要，不全量渲染巨图 |
| 新服务基础设施 | 不要求 Neo4j、向量服务、JDK、JDT LS、Maven/Gradle 构建作为首版依赖 |
| 跨项目/跨服务关联 | 同一项目根下的多模块可以分析；跨已打开仓库、HTTP 服务间自动拼图后续再议 |
| 编辑与执行 | 不修改源码、不修复代码、不运行用户代码、不执行模型给出的 shell/SQL |
| 新项目管理器 | 首版从现有仓库标签进入；任意非 Git 文件夹的“打开项目”产品流程后续再议 |
| 分享与持久知识库 | 首版不做团队协作、公开链接、图文件导出、跨会话问答历史或业务知识人工标注库 |

服务层必须能对无 `.git` 的目录进行分析；宿主 UI 复用仓库选择仅是路径与会话接入，不代表理解引擎依赖 Git。原有 Git 功能及其壳层保持自身行为。

### 3.3 交付阶段

M0 建立契约与验收样例；M1 索引事实和 Java 通用语义；M2 Spring 语义与有界图查询；M3 自然语言理解服务；M4 原生 UI；M5 综合验收。M1/M2 是内部里程碑，不能以“Java 后续增强”为由将两条路线拆成首版和未来版。

## 4. 用户流程

### 4.1 第一次进入

用户点击左侧“代码理解”，页面显示当前项目名称、索引状态以及一个问题输入框。无索引时主动作是“建立代码索引”，明确复用设置中的索引开关；建立完成后自动出现概览，不自动发起 AI 请求。已有索引时直接可探索。停用但有数据时允许查看现有数据，显示“索引已停用”，提供“启用并更新”。

### 4.2 提问并找到入口

用户输入“订单创建流程在哪里”。系统先检索符号、路径、注释及框架入口，再生成回答。如果同时命中多个不同业务入口，展示有名称、模块和匹配理由的候选，允许点选；不默默选择第一项并声称唯一。候选不足时说明检索范围与缺失证据，给出缩小范围的操作。

中文问题对应英文标识符时由 AI 在受控预算内生成查询词并检索；原问题和精确标识符均保留。未配置 AI 时不承诺跨语言语义检索，提示“可先用类名、方法名或路径搜索”。

### 4.3 理解与核对

回答优先给出入口、关键步骤与边界；点击步骤高亮图中相关节点，点击节点打开只读源码，点击边查看调用位置或声明依据。业务步骤编号表示阅读顺序；图中的调用箭头表示静态关系，不表示全部分支都会执行。

### 4.4 继续探索与恢复

用户可展开调用方/被调用方、查看接口实现、只看某模块、排除测试、返回上一次视图，或针对当前选择追问。修改范围会产生新请求代际，旧结果不覆盖新页面。切换标签或退出此模式会保留已完成结果并取消本次正在生成的问答；返回时显示已有结果和“已停止，可重试”，首版不做隐形后台继续问答。

## 5. 功能要求

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| CU-01 | 独立纯代码上下文 | 服务集成测试用无 Git 目录通过；问答工具无 Git、shell、写文件能力 |
| CU-02 | 索引状态与一致性 | 区分未建立、构建中、可用、已停用、可能过期、失败、需要升级；一次结果绑定同一代索引 |
| CU-03 | 项目概览 | 按模块/包展示入口与聚合关系，附范围和覆盖说明；统计不是业务结论 |
| CU-04 | 自然语言找逻辑 | 中文业务问题可找到英文符号；有歧义时展示候选；零命中不得补造入口 |
| CU-05 | 关系探索 | 支持调用方/被调用方、继承/实现、模块范围和测试过滤；节点/边数受限且显式截断 |
| CU-06 | 证据驱动解释 | 每条代码行为结论有可解析的证据 ID；无法确定处单列；引用行号不能只由模型输出 |
| CU-07 | 逻辑可视化 | 图、解释步骤、源码联动；多分派、环、外部依赖、未知边界可读；支持平移/缩放/适应画布/返回 |
| CU-08 | 普通 Java | §6.1 所有“必做”语法与关系通过样例；同名/重载不串符号 |
| CU-09 | Spring Boot | §6.2 路由、注入、持久化边界可串联；框架推断与语法事实明确区分 |
| CU-10 | 原生入口 | Context Navigator 增加“代码理解”，沿用壳层与主题；源码打开不绕道追溯页 |
| CU-11 | 生命周期 | 同项目单问答、全局最多 3 个 AI 在途任务共享名额；取消/重试/切换/迟到消息不污染状态 |
| CU-12 | 只读与数据范围 | 源码读取限定项目允许目录；路径越界和敏感文件被拒绝；不执行项目构建或模型指令 |
| CU-13 | 有界性能 | 达到 §7 预算与测试目标；所有重型检索、布局、文件读取离开 UI 线程 |
| CU-14 | 接口兼容与接手 | 既有符号面板和 MCP 保持可用；有版本化协议、迁移说明、测试样例与任务交接记录 |

## 6. Java 首版能力矩阵

### 6.1 普通 Java：必交付的静态理解能力

| 能力 | 首版深度 | 无法确定时 |
| --- | --- | --- |
| 项目结构 | 包声明、显式/通配/静态导入；Maven/Gradle 常规源码根、同根多模块；测试源集分开 | 动态 Gradle 配置只提示识别不完整，允许按目录缩小范围 |
| 类型和成员 | class/interface/enum/record、嵌套类型、构造器、字段、方法、参数/返回类型、注解和 Javadoc | 匿名类/局部类使用本文件局部身份，不承诺跨编辑稳定 |
| 继承和实现 | 类型继承/实现、可核对的方法 override 关系、声明方法与实现候选 | 外部父类型显示外部边界；不虚构源码 |
| 调用解析 | 保存每个调用点；优先声明类型、作用域、导入、参数个数和可证明类型；区分静态/实例/构造调用 | 不完整类型和复杂泛型保留多候选或未解析；已覆盖的 Java 编译期重载规则（如 null→引用类型、primitive widening 优先 boxing）按规则解析 |
| 局部变量与链式调用 | 明确声明的局部/字段/参数类型、`new`、可证明返回类型、有限 `var` 推断 | 复杂数据流和运行时多态不强行选实现 |
| lambda/方法引用 | 记录代码范围、包含关系、可确定引用目标；函数式目标缺失时保留候选 | 不声称回调何时执行，不伪造 Stream/异步顺序 |
| 方法内部逻辑 | 保留条件、循环、异常、返回语句的源码范围，供解释引用 | 不构建完整 CFG/PDG；不把调用顺序等同执行路径 |
| 现代语法 | 在固定 tree-sitter-java 版本上验证 Java 8/11/17/21 常见非预览语法 | 新预览语法、解析错误以局部覆盖缺口呈现 |

上述是本产品的有限静态语义能力，不是对整个 Java 语言的编译器级支持承诺。

### 6.2 Spring Boot：与普通 Java 同等必交付

| 能力 | 首版深度 | 明确限制 |
| --- | --- | --- |
| Web 入口 | Spring MVC 注解式 Controller/RestController；类+方法 RequestMapping 和 Get/Post/Put/Delete/PatchMapping；多个路径/HTTP 方法；常量可解析时组合 | 不读取运行时路由表；占位符、接口继承映射、未解析组合注解保留表达式与缺口 |
| Bean 识别 | Component/Service/Repository/Controller、Configuration + Bean；FQN 校验避免同名注解误识别 | 声明了 Bean 不等于运行时已激活 |
| 依赖注入 | 构造器（含单构造器无注解）、字段、setter/方法参数；Autowired、Qualifier、Primary，Resource 的独立规则 | Profile/Conditional、工厂、扫描范围和集合注入保留条件/多候选；不模拟容器 |
| 业务链路 | Controller 方法 → 声明服务 → 可选实现 → Repository/Mapper | 每段依据可展开；注入关系不冒充方法调用 |
| MyBatis | Mapper 接口；XML namespace + statement id 精确关联；Select/Insert/Update/Delete 注解；SQL 片段来源可打开 | 动态 SQL 保留条件片段；不执行 SQL、不推断完整表血缘；Mapper 同名重载不静默一对一 |
| Spring Data JPA | Repository 继承边界、源码中的查询方法、Query 注解、Entity/Table 声明 | 不生成不存在的实现或最终 SQL；派生查询仅说明声明意图 |
| 其他框架标记 | Transactional、Async、Scheduled、EventListener、KafkaListener/RabbitListener 的声明位置和文字说明 | 首版不据此串接完整 AOP、事务、调度或消息运行链 |
| Lombok | 识别 Data/Getter/Setter/RequiredArgsConstructor 等常见声明，提示生成代码不可见；可保留带标记的注入候选 | 不运行注解处理器，不把生成成员当作可定位的真实源码 |

Spring 支持以常见 Boot 2/3 项目源码形态建立样例，兼容 `javax`/`jakarta` 常见注解命名。其他版本不作全覆盖承诺；框架能力按规则版本报告。

## 7. 非功能要求与量化目标

以下数字是开发预算和验收目标，不是已测成绩。验收统一记录 Windows x64、CPU、内存、SSD、构建 profile、冷/热缓存与模型配置。

| 项目 | 首版目标或硬限制 |
| --- | --- |
| 标准数据集 | 10,000 个源文件、100,000 个符号、500,000 条聚合关系；另设 50,000 文件压力集 |
| 索引预算 | 沿用最多 50,000 文件、单源码 1 MiB；资源解析也受总文件数与单文件预算约束 |
| 本地搜索 | 标准集热缓存 p95 ≤ 300ms，至少 100 次固定查询；不计网络模型耗时 |
| 局部图查询 | 默认 ≤ 40 节点/80 边，热缓存 p95 ≤ 500ms；显式展开单图硬限 120 节点/240 边 |
| 图探索预算 | 默认 2 跳、最多 5 跳；单查询最多扫描 20,000 条邻接记录或运行 2s，先到即停止并标注 |
| 布局 | 120 节点上限布局 p95 ≤ 150ms（后台）；相同输入与种子顺序产生稳定坐标 |
| 索引性能 | 标准集全量 ≤ 180s、1% 文件变更增量 ≤ 30s、索引额外内存峰值 ≤ 1 GiB；未达目标先优化/分期评审，不偷偷删 Java 范围 |
| 交互 | 点击操作下一帧可反馈；目标交互帧 p95 ≤ 33ms；禁止 render 内整图载入、全树扫描或模型调用 |
| AI 预算 | 每问最多 40 次工具调用、41 轮（含必要收尾）、单结果 8K 字符、累计工具结果 120K 字符、总输入估算 48K token；详细规则见设计文档 |
| 可取消 | 本地任务每个批次检查，取消反馈 ≤ 1s；AI 在下个流读取/轮次边界停止，网络空闲等待上界沿用客户端超时并显示“正在停止” |
| 引用完整性 | fixture 中有效引用解析率 100%；过期/越界/伪造引用不得渲染成有效源码跳转 |
| Java 精度 | 两条样例集分别计算；受支持的确定关系 precision ≥ 98%、recall ≥ 85%；歧义用例强行唯一解析数必须为 0 |
| 自然语言定位 | 普通 Java 与 Spring 各至少 20 个固定问题；各自入口 Recall@5 ≥ 85%；人工评分与确定性检索回归分开记录 |

解析精度按人工标注的“调用点 → 声明目标”评估，不用候选实现充数。框架候选关联单独计算精度；降低确定关系召回率以避免错误时须明确说明。

## 8. 产品状态与提示

| 状态 | 界面说明与动作 |
| --- | --- |
| 无活动项目 | “先打开一个项目，再理解代码”，走现有打开流程 |
| 无索引 | “建立代码索引后，可查找业务入口和调用关系”，主按钮建立索引 |
| 正在建立/升级 | 阶段与进度；已有可读版本继续浏览；首次建立时禁止提问并解释原因 |
| 已停用但有数据 | 可浏览旧索引；发起新问答前选择启用更新或明确使用旧数据；引用仍校验 |
| 外部编辑/索引更新 | “代码已变化，当前结果基于较早索引”，更新动作；旧节点不自动跳到新行 |
| AI 未配置/不支持工具 | 保留本地探索；显示设置入口或供应商错误，不显示空白聊天页 |
| 零命中/解析不完整 | 显示实际搜索范围、覆盖缺口；不使用“项目不存在该功能”的确定表述 |
| 多实现/动态关系 | “存在多个候选实现”“运行时条件未知”，允许分别探索 |
| 达到预算 | 保留已证实结果并标注“结果不完整”，提供缩小范围/重新提问 |
| 请求失败/取消 | 保留已确认的图与源码，失败文本可重试；未完成 AI 内容不能标为最终答案 |

## 9. 最终验收演示

普通 Java 样例：输入中文需求，定位英文命名的入口；展开接口的多个实现；点击调用边查看真实调用点；重载歧义不被抹掉；无 AI 时依然能搜索和查看关系。

Spring Boot 样例：输入一个 HTTP 业务问题，找到映射注解，沿 Controller → Service 声明 → 条件化实现 → Mapper → XML/注解 SQL 查证；显示注入候选及动态 SQL 边界。任何缺失环节不得由模型凭空补线。

一致性样例：提问期间修改文件并发布新索引，旧请求停止使用新证据；切换项目后旧事件不串页；删除文件后引用呈现失效原因；不通过 Git 来判断变化。

以上演示与 CU-01～CU-14 全部通过后，才可将本功能标为首版完成。
