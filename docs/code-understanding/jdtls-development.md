## 1. 开工入口

先读根 [AGENTS.md](../../AGENTS.md)、[交接入口](README.md)、[接入设计](jdtls-integration.md)，然后检查本文件状态表和最新 `validation/jls-t*-handoff.md`。已有CU2能力见 [T1工具](validation/cu2-t1-handoff.md)、[T2/T3 agent](validation/cu2-t2-handoff.md)、[T4会话](validation/cu2-t4-handoff.md)和[真实模型验收](validation/cu2-t3-live-acceptance.md)。历史报告的“下一步”不能覆盖当前任务状态。

实现前检查工作区变化与实际接口；代码发现优先图工具，过期/不足时才读已定位文件。不得清理其他任务的变更，不提前重构已有Java解析器，不把历史测试当本批测试。本文只安排后续开发，不要求启动其他agent。

默认从最早未完成且依赖满足的任务开始。每个任务通过后更新状态与交接，可在同一开发任务中顺序推进，无需为每个内部步骤重新请求确认；真实缺少运行环境、模型配置或外部访问时记录缺口，继续独立工作，不宣称通过。

## 3. JLS-T0：先验证真实语义收益

当前核心完成，结果见[T0交接](validation/jls-t0-handoff.md)。本节保留原验证范围供回归使用。T1直接消费既有证据，补测尚未通过项；T4替换发行包后才针对新版本重跑必要用例。

**目标：** 用一个小型真实Maven工程先验证定义、引用、实现、入/出调用，再扩展普通Java、Gradle和Spring样例，确认值得接入。

工作项：

1. 记录当前提交、机器/OS/架构、基础索引规模。选定官方固定JDT发行包、服务JDK和样例项目JDK；记录版本、URL、SHA-256、实际启动参数。验证优先Windows x64/JDK21；不伪造尚未测过的平台组合。
2. 新样例放 `src/tests/fixtures/java_semantic/`，与已有CU2 fixture分开；不能为了让JDT通过而改掉原先用于验证索引缺口的样例。样例应有独立的源码位置/关系期望清单。
3. 最小验证程序或集成测试按stdio启动真实JDT，不引入GPUI页面和完整安装器。记录initialize能力、工程导入通知、依赖错误及文档同步方式；验证调用位置与定义位置。
4. 先跑同名login、重载、接口两个实现、跨模块调用四个问题；对照基础索引。只查到接口声明时不能算已确定实现，返回候选列表才是正确结果。
5. 增加普通Java源码/JDK、Spring+MyBatis/JPA、Gradle、项目目标Java8/17/21样例。Java8/17是兼容性测试目标，不代表用户真实生产环境。依赖无法获得时记录环境缺口；不得把未知结果填为通过。
6. 记录冷启动/首次导入时间、20次热查询的p50/p95、峰值RSS（含构建进程）、磁盘写入/缓存、超时降级。检查项目目录新增/修改文件，区分JDT元数据、构建产物和业务源码；不运行应用/SQL。

交付报告必须含：可复现命令、固定版本及校验来源、请求/结果摘要、源码位置期望与实际、误报/漏报、导入副作用、可支持平台/构建工具矩阵、下一步需要固定的初始化配置。

**进入T1的门槛：** 同名方法、重载、实现候选、跨模块调用在已导入Maven样例中得到正确结果；可取消/关闭真实进程；静态关系有可核对位置，且相对基础索引至少解决一个真实缺口。普通Java/Gradle等未通过项不能消失，进入后续限制台账，必须在T5支持声明前解决或明确不支持。若核心门槛失败，缩小定位问题继续验证，不进入UI或安装器掩盖问题。

## 4. JLS-T1：公共客户端、官方插件与语义服务

**目标：** 一个可共享、可取消、有界的LspSemanticService，公共LSP客户端与JdtLsProvider分离，不依赖UI和模型；首版仅注册 `java-jdtls`。

建议职责路径均为拟新增，统一位于 `src/lsp/`：

| 位置 | 职责 |
| --- | --- |
| mod.rs / service.rs | LspSemanticService、公共DTO、锚点/路由/缓存与消费者状态 |
| client.rs / protocol.rs | stdio帧、请求配对、通知、取消与标准协议类型 |
| process.rs | 按LaunchSpec启动、句柄/所有权、退出/回收 |
| plugins.rs | LspPluginDescriptor、SemanticProvider边界、仅一个官方条目的静态注册 |
| providers/jdtls.rs | Java启动配置、工程导入/就绪判定、JDT通知和查询差异 |

小型职责可合并文件，不同时维护旧java_semantic与新lsp实现。测试放 `src/tests/lsp*.rs` / `java_semantic*.rs` 并接入现有测试入口；T0 fixture不移动。不得先建第三方插件API、动态库加载器或脚本执行器。

工作项：

- 按设计第3.1节定义静态描述：plugin_id=java-jdtls、adapter_id=jdtls、descriptor_version、Java语言/操作、stdio运行环境、引擎包与已测兼容清单。注册表只读已编译数据；未知schema/ID、重复ID、语言冲突明确拒绝。
- 通过SemanticProvider把JDT专用参数、初始化设置和导入通知与公共层隔离。UI/AI只见统一服务，不能传LaunchSpec；provider根据已验证配置生成它。静态描述无任意shell命令或执行入口。
- 有效操作取描述、适配器实现和服务器协商的交集；测试静态声明有能力但服务器缺失/撤销时返回unsupported。保留query_java_semantics外部工具名，不给模型传插件ID和切换provider的权限。
- 使用现有std线程、async-channel和serde风格。实现Content-Length帧读写、分片/连帧、请求ID配对、服务端请求与通知、错误响应；写入串行，读循环独立。日志走stderr/独立文件，不污染stdout协议。
- initialize/initialized、必要配置、progress、能力注册、shutdown/exit按T0已核实版本实现。动态watch注册若声明支持，就必须有实际事件同步；不要只回成功。
- ServiceStatus、插件注册/启用、包安装状态分离；建立导入完成/partial判定，不能把initialize回复就标Ready。手动配置由受控provider转换为LaunchSpec，T1不下载、不修改系统环境。
- 实现设计第4节五种操作、document_symbols辅助定位、服务端opaque item保存、返回去重和预算。查询原子串行，prepare和后续查询不交错。
- 输入锚点绑定项目、hash、位置；LSP零起始/UTF-16与源码字节范围互转。无准确selectionRange时返回歧义，不能用同名字符串第一个命中顶替。
- 返回显式caller/callee/call_site；保留coverage、provider=jdtls、plugin_id、engine_version、epoch、revision和截断原因。事件/缓存同样绑定插件和版本，禁用或切版本后旧结果失效。外部依赖仅保留目标提示，未通过SourceService白名单的文件不可读。
- 实现文件/构建配置变化监听和失效；请求前后核验revision和源码hash。循环缓存受16MiB/128项限制；索引generation改变仍遵守CU2会话规则。
- 全局单JDT进程、有限队列、3秒操作期限、取消/迟到结果丢弃、空闲回收、最多一次故障自动重启。服务退出回收自己拥有的进程，不影响其他IDE的Java进程。

承接T0明确待补事项：实际取消而非仅发送cancel通知；UTF-16/emoji/CRLF；文件变化与依赖缺口；真实JDK8/17路径映射；工程元数据写入行为；Gradle daemon所有权与退出。先验证私有Gradle用户目录等隔离方式，不能关闭共享daemon来通过“无残留”测试。使用T0本地snapshot仅属手动开发例外，记录版本/散列并显示开发构建，不假装已完成托管版本校验。

验证分两层：fake LSP覆盖协议和异常，真实JDT复跑T0查询样例。必须覆盖分片、错误长度、超大帧、请求乱序、服务端反向请求、null/多候选、取消仍回结果、初始化未完成、跨项目隔离、同项目多消费者、进程退出、中文/emoji/CRLF、URI与根外链接。

**完成门槛：** 自动协议/插件注册/能力/来源/生命周期测试通过，真实查询位置正确；服务不可用或插件被禁用不破坏基础索引。记录公共层与JDT层接口、能力交集和进程清理证据，不能只提供“可以启动java”的截图。无需第二个生产provider证明可扩展，用fake provider验证路由即可。

## 5. JLS-T2：AI接线与业务对照

**目标：** 让现有Understanding Agent直接使用语义定位，保持AnalysisResult及来源校验。

修改范围以 `src/code_understanding/tools.rs`、`agent.rs`、必要的source/session适配和对应测试为主；不能引入第二套agent循环或降低sr1来源验证。

工作项：

1. 扩展候选注册表的合法源码锚点；实现 `query_java_semantics` 的operation枚举、tagged anchor和limit校验，内部只调用LspSemanticService，不引用JDT启动/导入细节。工具列表在一问开始冻结；ready/禁用/能力变化通过响应说明，不允许模型等待/安装/重配插件。
2. trace_calls保留旧输入与导航输出，增加可选的一跳semantic部分，明确depth=1、端点、位置、来源。timeout/未ready时基础结果照常返回；与基础索引冲突不静默合并。
3. 语义定位到未索引符号时，引导读取允许路径和当前范围，不制造sc1或索引边。对外部依赖、候选多实现、源码过期分别提示。
4. 提示词要求AI核对调用位置和实现条件，沿Mapper/XML/SQL继续读；不能把“JDT返回”视为表读写或Spring运行行为的证明。原答案JSON结构与15步骤/20连接上限保持。
5. 将语义查询计入现有40工具、8K单结果、120K累计字符预算；内部查询另受每工具6RPC/每问40RPC约束，缓存命中仍计工具/字符。连续失败只提示一次并继续基础路径，避免重复调用耗尽预算。
6. 使用同模型、同问题、同温度和预算，开/关增强各跑两遍。记录模型/版本、工具轨迹、耗时/输入量、调用准确性、表读写、未知项，不能只比较答案长度。

**完成门槛：** 核心Java定位样例有真实改善，业务回答仍有可核验来源；已有B01～B05基础模式回归通过。模型不可用时协议测试可以交付，但真实模型验收必须保留未完成状态。语义正确性以人工或独立期望清单判定，不让同一次模型输出给自己打分。

## 6. JLS-T3：原生源码与关系视图

**目标：** 用户可以从业务回答进入源码，查定义/实现/引用/调用并继续追问。

前置核对CU2-T5当前实际文件和页面；本设计时它尚未完成，后续agent不得照旧路径再建第二个页面。等待UI接口时可实现纯状态与DTO，不绕到HTML伪装原生验收。

- LspSemanticService通过UiEvent接入，render不做I/O。每次导航带plugin_id/engine_version/项目/视图/request/epoch身份，离页、切项目、禁用插件或引擎切版本时丢弃旧消息。视图不包含JDT特有启动和导入判断。
- 动作按有效能力启用；未支持的能力明确说明，可转基础搜索，不伪造语义导航。全局禁用插件后本地源码和已有来源仍可按原规则查看。
- 方法/符号位置提供设计第8节鼠标动作；同一个侧栏显示结果列表并返回源码，多实现保留选择，长路径允许查看全名。
- “解释此处”把已验证选择作为下次提问焦点；AI仍重新核对来源。纯本地导航不要求AI已配置。
- 业务简图继续消费AnalysisResult，一跳调用按需展开，不按引用顺序拼业务流程；图节点与关系位置可分别打开。
- 暂提供手动环境的高级设置与项目增强开关，为T4/T5安装状态留接口。安装缺失时提示未安装，不让所有源码动作失效。
- 复用Focus Workbench、主题token、syntect、虚拟列表、分隔条和反馈helper；不新增键盘行为。

**完成门槛：** 实际GPUI页面检查深浅主题、长路径、窄窗、中文/IME、取消、返回、切项目、过期引用；记录截图/操作证据和无法自动验证的人工项。代码编译或fake UI状态通过不能代替原生交互验证。

## 7. JLS-T4：官方插件引擎包与运行环境管理

当前核心完成（服务层 + 真实官方包验收，见[T4交接](validation/jls-t4-handoff.md)）；设置页入口与安装进度UI属T5。本节保留原任务范围供回归使用。

**目标：** 无需捆绑JDK，也不要求普通用户自行寻找JDK/JDT目录。此任务实现服务，T5提供完整入口。

拟新增 `src/lsp/runtime/java.rs`、`install.rs`，插件描述引用小型内置EnginePackageSpec清单；复用已有ureq、sha2、zip和directories。确需支持tar格式才增加对应小型依赖，不为全平台框架引入大型包管理器。适配器代码仍随应用发布，下载内容只有引擎及其运行环境。

工作项：

1. 按设计第6.3节有限检测JDK路径，记录候选来源/版本/架构/完整性；显式路径失效不静默替换。项目JDK与服务JDK独立，系统JAVA_HOME/PATH原样保留。
2. 按T0发行限制补齐固定官方发行归档URL/SHA，复跑核心查询后建立真实EnginePackageSpec；当前本地snapshot不直接进入托管清单。清单绑定plugin_id、当前编译适配器已测版本和平台/JDK组合，未知组合拒绝托管激活。保留许可证和来源并核对具体告知要求，不从历史对话直接推导。
3. 下载采用内置固定清单、HTTPS/可信发行域名及必要重定向域名白名单，逐跳检查；禁止模型/项目配置指定任意安装URL。应用代理错误明确失败，不静默切换网络路线。
4. 实现单安装任务与跨进程互斥、流式下载、实际大小上限、SHA校验、有界解压、入口验证、原子发布和激活记录。主程序更新流程可以复用小型底层能力，但不复用会重启/替换Khaslana自身的动作。
5. 安装包压缩/展开/条目限额写入固定清单，并以实际读取/写入计数执行；归档路径检查、解压失败、下载取消均不得修改激活版本。网络读空闲期限设30秒，取消在读/写/解压边界生效；UI立即标“正在取消”，后台真正退出后才释放任务槽。
6. 日志保存阶段和错误码，不记录密钥/代理secret；下载进度事件节流。安装失败区分网络、代理、磁盘、校验、解压、入口、版本/架构不兼容。
7. 新旧版本使用独立目录，激活失败不丢旧版本；占用中的版本禁止卸载。只允许清理registry确认由本应用拥有且路径归属正确的包，不能删除用户JDK或其他IDE缓存。
8. 安装权限不足、平台不支持或断网时保留手动配置路径。Windows x64托管路径必须实测；其他平台没有真实测试/发行清单就明确不支持一键安装，不能隐式下载错误架构包。
9. 按设计第6.4/6.5节以plugin_id管理包目录、激活记录与设置；运行环境独立记录但不注册为插件。拒绝从下载包或项目目录加载新的manifest/adapter。注册表、适配器兼容清单只随应用更新，首版不提供热更新适配器能力。
10. 更新时先校验新版本组合，旧进程退出后再切换激活版本，递增会话身份并失效缓存。失败保留旧包和激活记录；退出前收到的结果不能在新版会话展示。卸载只针对私有包，保留官方注册条目和手动配置入口。

验证：本地可控HTTP服务模拟断流/重定向/错误长度/校验失败，人工构造穿越/重复目标/链接/膨胀归档，模拟取消与磁盘失败；检查旧激活记录与目录完整。另用一次真实官方包跑安装及JDT启动，fake下载不能代替。

**完成门槛：** 有可重复的首次安装、已有JDK复用、取消、失败恢复、更新失败回退、卸载保护证据；环境变量及用户JDK未变。安装器发布的是可启动的完整版本，不是“文件已下载”。

## 8. JLS-T5：插件管理入口与最终交付

**目标：** 将T3语义入口与T4安装服务连成用户可完成的流程，并完成整体回归。

- 现有代码索引设置内增加“语言支持”区域，首版只有一个官方Java插件卡，显示名称、已安装引擎版本、兼容/能力状态。全局插件启停与安装/更新/卸载属于该卡；项目卡只控制项目增强和导入授权。高级配置可展开，不新建插件市场或商店页面。
- 默认先检测；未安装时显示安装入口，展示要下载的组件、大小、位置；用户确定后才下载。安装结束显示Installed，随后按项目已授权状态启动/导入；Ready才展示增强可用。
- Missing/下载中/正在取消/Failed/Installed/Importing/Partial/Ready状态与按钮对应，避免多来源进度互相覆盖。设置页关闭后在原入口能重新查看或取消安装；应用退出取消安装。
- 依赖导入失败提供重试/配置提示，AI继续基础模式；启动不要求修改业务项目JDK。用户关闭增强后不再启动服务，现有结果按来源规则查看。
- 更新与卸载只管理私有包；使用用户JDK时显示来源并隐藏卸载该JDK的动作。
- 区分注册、已安装、已启用、项目ready四层状态；全局禁用保留包和项目偏好，取消查询并释放自有进程，重启应用后保持禁用。重新启用不自动下载。卸载引擎后官方插件卡仍在并显示“未安装”，不声称已删除编译适配器。

**完成门槛：** 在干净测试环境完成“无合适服务JDK → 安装 → 授权项目导入 → Java问答 → 源码导航”，并在已有合适JDK环境证明不重复下载JDK。再次启动复用安装；断网/代理失败、取消重试、项目导入失败、关闭增强都能恢复基本使用。最终运行本文件第9节矩阵并提交统一报告。

## 10. 交接格式与范围控制

每个任务结束必须更新第2节状态，创建对应报告；不得仅写“完成，请继续下一步”。报告至少包含：

```text
任务号、完成/部分完成状态、日期、代码提交/工作区基线
实现的需求编号与修改文件；复用的公开接口与实际调用示例
固定JDT/JDK版本、平台、项目JDK/构建工具、下载与校验来源
plugin_id、描述版本、编译适配器版本标识、引擎兼容清单及实际协商能力
测试命令、实际执行数量、失败/跳过项；release构建结果
真实查询/模型对照/安装/UI证据及关联验收编号
资源与导入副作用记录；已知限制、未解决问题
配置/数据目录变化、兼容性、停用/回退方式
下一任务、可直接复用接口、仍需完成的验收
```

报告中的原始协议/源码只保留合成测试项目内容，真实项目日志不得提交secret或无关源码。第三方二进制、JDT工作目录、下载缓存不进入Git；T0锁定清单和小型fixture可入库。

未完成事项分为：实现缺陷（继续修）、环境缺口（记录复现条件）、产品范围外（引用设计边界）。不得把这三者统称为“后续优化”后标完成。整个Java增强只有T0～T5所需证据齐全才完成。

暂缓清单：Kotlin/商业Provider、第三方插件市场、动态DLL/脚本宿主、适配器独立热更新、全量JDT关系落库、源码反编译、全框架规则、运行时追踪、补全重构和自动后台更新。官方静态注册与Java插件管理已属于本版任务，不能再以“插件平台暂缓”为由跳过。遇到真实MyBatis定位断点可先改检索/提示；确需小规则时写明失败样例和最小改动，不恢复旧DEV-05/06大型排期。
