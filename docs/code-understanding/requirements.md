# AI 代码理解需求文档

版本：2.0。日期：2026-09-10。状态：当前产品基线。
本版替代 v1 的重型静态分析范围，调整原因见[范围记录](scope-change-v2.md)。

## 1. 产品目标

用户输入“登录逻辑怎么实现的”，AI 自动查找相关代码并沿线索阅读，回答：

1. 登录入口及触发方式在哪里？
2. 核心处理步骤是什么，调用了哪些方法/服务？
3. 这些方法被哪些代码调用？哪些是直接调用，哪些是间接或框架触发？
4. 查了哪些表，新增、修改或删除了哪些表中的数据？分别在什么条件下发生？
5. 有哪些校验、失败分支、事务声明、缓存/会话、令牌、外部调用等相关逻辑？

关键代码与数据访问结论均可点回来源。答案附一张易读的流程简图，支持继续问“密码校验在哪”“失败会不会写日志”“谁还会调用这个服务”。

索引负责缩小范围、指路；AI 负责结合源码解释业务。索引不完整可以继续搜索，不能成为业务问答的硬阻塞。

## 2. 首版闭环

**输入问题 → AI 搜索入口 → 阅读源码及上下游 → 查证数据访问 → 输出解释/简图/来源 → 追问。**

用户不需要先选中方法、理解图查询或配置 Java 工程。AI 能区分的多个入口直接说明并分别分析；只有歧义显著影响答案时才向用户询问范围。

“谁调用了它”默认列与当前问题相关的直接调用方，必要时继续向上找触发入口；“调用了什么”展开关键业务方法与副作用边界，不把所有工具函数平铺。始终注明检索范围和遗漏可能，不默认声称找齐所有调用。

## 3. 首版范围

| 必做 | 深度 |
| --- | --- |
| 业务自然语言问答 | 中文问题定位英文命名代码；支持普通 Java、Spring Boot，保留已有其他语言索引能力 |
| 上下游调用理解 | 现有调用索引优先，缺失时按名字、接口、导入和源码搜索补查；区分直接调用、间接调用和候选 |
| 数据读写理解 | AI 读取 SQL、Mapper XML/注解、Repository、实体映射，列出读写对象、操作、条件和来源 |
| 其他相关逻辑 | 阅读校验/异常/返回、缓存、令牌/会话、消息或外部接口；是否展开由问题和代码决定 |
| 解释与来源 | 每项关键行为有源码引用；事实、推断、未确认分开表达 |
| 回答流程简图 | 当前问题的少量业务步骤与副作用节点；可点击来源，不依赖数据库已有全部图边 |
| 多轮追问 | 携带当前问题、最近答案摘要及选中代码范围，按需重新查证 |
| 原生页面 | 一个问题输入区、回答主区、按需源码侧栏；复用现有索引与 AI 设置 |

首版不做：Java 编译器级重载/泛型求解、Spring 容器模拟、完整静态 SQL 血缘、字段级数据流、所有运行时分支证明、JDT LS 集成、全仓库自动业务建模、巨型交互图编辑器、向量服务、后台全仓库 AI 摘要、跨仓库链路、团队分享和持久问答库。

已有静态能力可以使用，但其进一步补齐不构成本版完成条件。普通 Java/Spring 都是业务问答验收对象，不再要求语言特性矩阵全覆盖。

## 4. 数据读写的产品语义

读写表分析是首版核心，不可只回答“到 Repository 为止”。

| 代码证据 | 可以回答什么 | 不能做什么 |
| --- | --- | --- |
| 明确 SQL 与静态表名 | SELECT 读、INSERT/UPDATE/DELETE 写；说明条件和被修改内容 | 将 SQL 的全部名字当物理表；忽略别名、CTE、子查询或分支 |
| Mapper XML/注解 SQL | 结合调用方法、namespace/id 或注解查证，再列读写与条件 | 仅靠方法名断言表名；执行动态 SQL |
| ORM 方法 + 明确实体表映射 | “按实体映射推断读取/更新某表”，附调用和映射双来源 | 假装看到了最终 SQL 或运行时命中记录 |
| 只有实体类名/方法名 | 报告对象或查询意图，标物理表名未确认 | 用类名猜一个确定表名 |
| 动态表名/存储过程/缺失外部实现 | 展示原始表达式、已知操作和未知边界 | 虚构展开后的表名、过程内部读写、触发器或 ORM 级联副作用 |
| Redis/缓存、HTTP、消息 | 单独列为缓存/外部调用/消息副作用 | 混进关系数据库“表”清单 |

同一表可能同时出现“读”和“写”。失败分支的登录日志、计数更新也要检查，不能只讲成功路径。已确认“这次条件下不写库”与“在已读范围未发现写库”是两种不同结论。

首版分析的是代码可见行为，不连接数据库验证；无法由源码确定的物理对象类型（表/视图等）需说明。

## 5. 期望答案示例

以下是**假想登录样例的呈现方式**，不代表当前 Khaslana 存在这些类或表。实际答案必须来自当前项目。

“登录请求由 LoginController 接收，AuthService 查找账号、校验状态和密码。成功后创建会话，并更新最后登录时间；密码错误时返回失败，同时记录尝试。当前找到的业务入口是账号密码登录，短信登录另有入口。”

| 对象 | 操作 | 发生条件 | 来源 |
| --- | --- | --- | --- |
| app_user | 读 | 按账号查找用户 | UserMapper 查询 SQL |
| app_user | 写：UPDATE | 校验通过后更新最后登录时间 | 更新调用 + UPDATE SQL |
| login_attempt | 写：INSERT | 按样例的成功/失败分支记录尝试 | 分支调用 + INSERT SQL |
| Redis 会话键 | 缓存写入，非数据库表 | 登录成功 | SessionService 源码 |

答案还应提供：

- 调用方：找到的 Controller、其他直接调用位置及搜索范围。
- 关键调用：查用户、密码比较、会话创建、记录尝试；细节可继续展开。
- 分支说明：账号禁用、密码错误、外部存储失败等，仅按代码实际支持的内容写。
- 流程简图：主流程与已查证的失败分支，点击步骤打开源码。
- 未确认：例如动态表后缀、外部认证服务内部实现、由运行配置决定的 Bean。

示例表格的来源栏在产品中是实际文件和行范围按钮，不是固定文案。

## 6. 功能与验收要求

本版使用 CU2-R 编号；旧 CU 编号仅在归档内保留。

| ID | 要求 | 验收 |
| --- | --- | --- |
| CU2-R1 | 自然语言找到业务入口 | 不预先选择文件，中文问题能定位样例的登录入口及关键实现 |
| CU2-R2 | 查明调用上下游 | 同时报告相关调用方/被调用方；缺索引边时能通过源码搜索找到至少一条缺失关系 |
| CU2-R3 | 查明数据读写 | 明确 SQL 表名/操作准确；ORM 推断有映射证据；动态表名不编造 |
| CU2-R4 | 讲清业务流程 | 说明关键校验、成功/失败分支和其他副作用，而非只列函数名 |
| CU2-R5 | 证据与不确定性 | 关键行为有有效源码引用；AI 推断标注；“未找到”不等于“不存在” |
| CU2-R6 | 简图与追问 | 简图对应答案、可定位源码；追问可深入当前逻辑，不串项目 |
| CU2-R7 | 轻量原生入口 | 复用项目壳层与 AI 设置，输入/取消/重试/源码查看形成完整闭环 |
| CU2-R8 | 运行边界 | 不含 Git/写文件/执行/数据库连接工具；有限读取、取消和旧结果保护生效 |

## 7. 用户状态

- 无项目：引导沿现有流程打开项目。
- 无索引：引导建立已有代码索引；不要求“Java 深度分析完成”。
- 有索引但部分语言/关系缺失：照常问答，AI 使用源码搜索补足并报告限制。
- 索引更新或文件变化：已有结果可保留并标旧；引用校验失败则提示重新分析，不能悄悄跳到新行。
- AI 未配置或不可用：给设置/重试入口，保留现有本地符号检索；不承诺离线自然语言理解。
- 生成中：显示“正在查找入口/阅读调用/核对数据库访问”等简短进度；可取消。
- 达到预算：呈现已完成的部分、未查完的范围与继续分析建议，不冒充完整答案。
- 切换项目/离页：取消该次生成，保留已完成答案；迟到消息不能回填别的页面。

不做跨会话历史持久化。首版同项目一个问答任务；并发和 AI 传输行为尽量复用现有设施。

## 8. 完成标准

首版以业务问题验收，不用 Java 语法规则数量衡量进度：

- 至少三个小型样例：普通 Java 登录、Spring + MyBatis 登录、Spring + JPA 登录；另设缺边、动态表、多入口的边界变体。
- 每个主样例从一个问题产出入口、上下游、读写表/对象、关键分支、有效来源和简图。
- 所有标注的关键结论由所引代码支持；不存在伪造表名/调用关系或把推断当确定结果。
- mock 传输/工具测试通过，真实模型按固定问题重复运行并留报告；模型不可用时明确剩余验收。
- 窄窗/深浅主题、取消/重试/切换、源码过期及已有索引/MCP/AI 功能回归完成。

详细预算和实现顺序见[设计文档](design.md)与[开发文档](development.md)。本轮只更新文档，不判定已有代码完成或失败。
