## 2. 重构相关问题

### R1 · P1：自绘模态弹窗没有隔离键盘焦点

**证据：** `src/ui/components.rs:683` 的 `dialog_overlay` 仅提供全屏布局和 `.occlude()`；`src/dialog_view.rs:147` 挂载内容但没有焦点约束；设置中心 `src/repository_ui.rs:626` 只有 `track_focus`。当前生产源码没有接入 Kit `focus_trap`。本地 `gpui-component 0.6.4` 的 Root 在没有 trap 时调用全窗口 `focus_next/focus_prev`；`.occlude()` 不提供键盘焦点隔离。

**触发与影响：** 打开确认框或设置后连续 Tab/Shift+Tab，可以沿全窗口焦点序列移到遮罩下面的 Kit 按钮/输入。底层工作区仍挂载且并未因普通弹窗打开而禁用，Enter/Space 可能激活用户看不见的操作。输入提交也没有统一的顶层模态归属校验（`src/repository_core.rs:1598`）。这是从普通控件鼠标交互切到 Tab 导航后必须补上的边界。

**修正：** 普通对话框、设置、凭据、AI 思考窗使用统一模态宿主，接入 Kit Dialog 或 `focus_trap`，打开时移动焦点；嵌套时只有最上层可接收键盘。提交动作增加当前可操作层校验，不能仅以某个宿主仍持有焦点为依据。

**验收：** 预先准备有暂存内容的临时仓库；确认框/设置中往返 Tab 至少两轮，底层提交/切换仓库/远端操作均不能被激活；嵌套弹窗关闭一层后回到父层。

### R2 · P2：深色主题颜色已切换，但 Kit mode 仍是 Light

**证据：** `src/ui/kit_theme.rs:106` 用 `Theme::from(&colors)` 重建主题，随后只设置圆角、字号、阴影和滚动条，没有设置 `mode`。本地 `gpui-component-0.6.4/src/theme/mod.rs:659` 的转换实现明确使用 `ThemeMode::default()`，默认值为 Light。`src/theme_view.rs:34` 之后没有再次修正 Kit mode。

**影响：** 选择深色后 `Theme::is_dark()` 仍为 false。Kit 输入组 `input/group.rs:295` 据此选择背景、禁用态和错误环透明度，所以这是已发生的分支选择错误，不只是潜在的未来兼容问题。

**修正：** 重建后按 `ThemeVariant` 显式写入 Kit `ThemeMode`；检查重建时其他依赖 mode 的派生状态，仅修正实际使用的部分。

**验收：** 浅→深→浅、跟随系统两方向切换，应用 variant 与 Kit mode 一致；同时核对输入框普通、禁用、聚焦与错误态。增加桥接测试，而非仅测试颜色常量。

### R3 · P2：设置中心固定高度超过最小窗口

**证据：** `src/repository_ui.rs:627` 固定宽 900px、高 640px；外层 `dialog_overlay` 居中，根 `app_shell_surface`（`src/ui/components.rs:288`）裁切溢出；没有按 viewport 限制面板高度。

**触发与影响：** 860×520 最小窗口中，640px 高面板在纵向居中后上下各越界约 60px，设置标题/关闭区与底部内容可能被裁掉。右侧内容区内部滚动不能修复整个面板越界。宽度也应一并按可用视口约束，不能依赖默认 flex 收缩。

**修正：** 采用 `min(设计尺寸, viewport - 安全边距)`；固定可见头部，主体 `min_h(0)` 内部滚动。顺带验证工作流编辑器等其他大弹窗，但不能未经复现就把它们全部记为同类缺陷。

**验收：** 860×520、1280×820，以及 125%/150%/200% DPI 下关闭、分类导航、保存动作始终可达；保留前后截图。

### R4 · P2：Esc 的关闭顺序与实际浮层层级不一致

**证据：** `src/main.rs:3697` 后先绘制普通对话框、再绘制 AI 思考窗；`src/repository_core.rs:1803` 的 Esc 分发却没有检查 `ai_thinking_overlay`，会继续走 `active_dialog`。工作流 AI 生成明确不设置全局 busy（`src/workflow_editor.rs:1971`），因此 `!busy` 不会挡住这个关闭。通用 `close_dialog`（1924）也没有执行编辑器专用 `close_workflow_editor`（`src/workflow_editor.rs:1405`）的状态清理。

**触发与影响：** 工作流编辑器中启动 AI，再按 Esc，会关闭被思考窗遮住的编辑器，思考窗仍在；生成结束后编辑器隐藏，不能按原路径展示回填结果。此外，普通 Esc 退出编辑器与点击其关闭按钮的生命周期不同，残留 `workflow_editor` 让动态宿主继续存活。

**修正：** 先根据实际顶层浮层决定是否消费 Esc。AI 若不可取消则拦截；若允许收起则复用“后台运行”语义，绝不能穿透关闭父层。编辑器、关闭窗口确认、凭据等通过各自关闭策略统一处理，明确未保存内容策略，不把 `active_dialog = None` 当成所有弹窗的等价关闭。

**验收：** 编辑器→AI 思考窗→Esc；编辑器子菜单→Esc→父层；编辑器普通关闭与 Esc 关闭；关闭窗口确认→取消。核对显示、草稿、宿主数量和后台结果归属。

### R5 · P2：动态输入宿主仅以位置复用，缺少业务身份

**证据：** `src/ui/fields.rs:160` 仅按 `FieldId::WorkflowInput(index)` / `StepParam { step, slot }` 保留宿主；`spawn_kit_field`（235）只在初建时写入 placeholder 和 focus；`sync_kit_field`（277）只同步字符串。`src/workflow_view.rs:421` 加载模板时整体替换 inputs；`src/workflow_editor.rs:1510` 移动步骤时交换业务字段，Kit 宿主不随之交换。

**可确定的影响：** 加载另一个具有同位置输入的模板后，Kit 仍显示上一个模板的 placeholder（placeholder 源为 `src/workflow_view.rs:280` 的 label）。新业务字段的 focus 也不会重新指向复用宿主。若两份业务字段文本恰好相同，同步直接返回，旧编辑的选区/撤销历史会跨字段身份保留；Kit `set_value` 虽会清除撤销历史，但这个相等分支不会调用它。

**修正：** 宿主键至少包含仓库、模板/编辑会话代际、稳定字段/步骤身份。身份更换时重建或完整重绑，不以“字符串相同”视为“同一输入框”；异步回调同时检查代际与实体身份。普通回填与业务对象替换分开处理，避免每次输入都清除撤销。

**验收：** 两个模板的同位置字段用不同 label、相同初始文本；切换后 placeholder 正确且 Ctrl+Z 不回到前一模板。再覆盖步骤交换/删除、AI 整体回填、跨仓库与编辑器重开，检查 focus 和回写目标。

### R6 · P2：菜单和设置导航仍存在键盘不可达路径

**证据：** `src/ui_helpers.rs:898`、928 的两个 context menu helper 仍是仅挂 `on_click` 的 div，没有焦点或方向键模型；应用于变更、提交、文件路径、标签、分支、远端、贮藏菜单。设置分类行 `src/repository_ui.rs:687` 与关闭按钮 655 也仍是普通 div。仅将两个远端选择器改成 Kit DropdownMenu 不足以覆盖这些通用交互。

**影响：** 菜单打开后方向键不能选择条目、Enter 不能按菜单语义确认；纯键盘不能遍历全部设置分类。与已确认的“菜单方向键、控件 Tab/Enter/Space”目标不符。

**修正：** 保留业务回调与危险确认，通用菜单迁到 Kit 菜单；分类/图标动作使用 Kit Button 或具备等价语义的导航组件。为每个条目使用稳定业务 ID，不能只靠中文 label。

**验收：** 菜单方向键循环、禁用项跳过、Enter 单次执行、Esc 关闭、触发器恢复；九类设置均可键盘访问。鼠标原行为保持一致。

### R7 · P2：Esc 关闭后聚焦根节点，未恢复原触发器

**证据：** `src/main.rs:3484` 在所有成功关闭后固定执行 `window.focus(&this.shell_focus, cx)`，不区分关闭的是子菜单、搜索框、设置还是对话框，也没有记录进入浮层前的焦点。

**影响：** 在编辑器里收起下拉后，焦点跳到应用根；接下来输入或 Tab 不再从原控件继续。对于嵌套浮层，“回到一个有效根节点”与计划要求的“恢复到触发器/父层”不是同一种行为。

**修正：** 浮层打开时保存弱焦点句柄；关闭最上层后恢复该句柄，目标已销毁才回退父层默认焦点，最后才回根。鼠标关闭与键盘关闭使用同一策略。

**验收：** 从输入、按钮分别打开菜单/弹窗，Esc 后输入或 Space 落在原触发器；条目删除导致原句柄失效时安全回退。

## 3. 顺带发现的原有生命周期问题

### R8 · P1（基线已有）：AI“后台运行”同时解除三业务互斥

**证据：** `src/ai_view.rs:54` 使用 `ai_thinking_overlay.is_some()` 作为公共生成任务互斥条件，但“后台运行”在 247 只把它设为 None，任务继续。`src/repository_events.rs:1483` 的增量没有任务 ID，直接写入当前 overlay；共用失败分支 1466 起复位多个业务 loading 并关闭当前 overlay。已用 `git show b4ec891:src/ai_view.rs` 确认该模式存在于重构基线，不归因为本次迁移新增。

**触发与影响：** 先启动提交信息生成并放入后台，再启动工作流模板生成。第二项通过公共互斥；第一项增量可能出现在第二项窗口，第一项完成/失败可能关闭第二项窗口或复位第二项 loading。

**修正：** 最小方案是将“任务运行态”与“弹窗可见态”分离，后台运行只隐藏窗口；任务完成才释放互斥。统一事件带任务身份，增量、成功、失败只影响所属任务；不要顺便重写已具备代际机制的 AI 评审 agent。

**验收：** 用可控假流模拟 A 后台、B 请求、A 迟到增量/成功/失败。若产品保持互斥，B 应明确被拒绝且其 loading 不残留；任务 A 结束后可正常新开。

### 测试与采证顺序

1. **自动化守卫：** 主题 mode；动态宿主身份/重排/替换；AI 可见态与运行态；顶层关闭路由。对焦点、实体订阅使用实际组件集成测试，避免再次只测枚举判定。
2. **真实键盘：** Tab/Shift+Tab、Enter/Space、菜单方向键、嵌套 Esc、快捷键录制、Ctrl+P；中文 IME 组合时 Enter、Ctrl+Enter；多行普通 Enter。Windows 注入遵循项目既定 PostMessage 路线或真实输入；明确记录所用输入方式。
3. **隔离 Git fixture：** 暂存/取消暂存/部分暂存两方向、普通提交/amend/提交并推送的守卫、merge/rebase/冲突、工作流与后台 AI。危险操作仅在临时仓库，不对用户工作树执行。
4. **视觉矩阵：** 860×520、1280×820、1440×900、最大化；浅/深与 100/125/150/200% DPI。重点看弹窗、长路径、禁用/错误/焦点、冲突和工作流。常规文字 4.5:1、关键图形 3:1 目标实际测量。
5. **性能矩阵：** 同机同 fixture、同 release profile，至少三次；10,000 行列表、20,000 行 diff 的 p95、启动到可操作、峰值内存；对照基线与既定预算，不用“保留 uniform_list”推定性能合格。
6. **完成门槛：** R1–R7 全部关闭；R8 独立闭环；必要自绘边界有文档；四项工程检查再次通过；未测项目不得标通过。只更新相关代码和文档，不夹带格式化或业务架构重写。
