# Khaslana 产品文档

> **版本**：v4（当前线上版本）
> **定位**：桌面端 Git 客户端，面向开发者提供仓库管理、版本控制、代码评审等全流程工具
> **技术栈**：Rust + GPUI（GPU 加速原生 UI）+ libgit2
> **平台**：Windows / macOS / Linux

---

## 一、产品概述

Khaslana 是一款原生桌面 Git 客户端，以中文为主要界面语言。核心能力包括：

| 能力域 | 说明 |
|--------|------|
| 仓库管理 | 打开本地仓库、克隆远端仓库、多仓库并存与仓库切换 |
| 版本控制 | 暂存/提交/推送/拉取/获取/分支切换/合并/变基/回滚 |
| 代码浏览 | 提交历史查看、分支浏览、文件对比（Diff） |
| 冲突解决 | 三栏冲突工作台，块级选择 Ours/Theirs |
| AI 辅助 | AI 生成 Commit Message、AI Code Review |
| 工作流引擎 | JSON5 定义自动化流程，支持变量插值与远端守卫 |
| 凭据管理 | HTTPS/SSH 凭据存储（系统 Keyring），远端凭据绑定 |
| 网络代理 | 不使用/系统代理/自定义代理三种模式 |

## 二、全局布局

Focus Workbench 采用应用壳层 + 专业画布的布局。自上而下是 **44px 自定义标题栏**、主工作区和底部状态栏；主工作区从左到右由 **Context Navigator**（展开为标题 + 模式按钮 + 引用分组，收起为 48px 窄条）和当前模式画布组成。

```
┌────────────────────────────────────────────────────────────────────┐
│  44px 标题栏：仓库切换  分支摘要  刷新/获取/拉取/推送  贮藏/子模块  设置  窗口控制 │
├────────────────────┬───────────────────────────────────────────────┤
│ Context Navigator  │                                               │
│（标题+模式按钮+分组； │  主模式画布                                    │
│ 收起为 48px 窄条，   │  Review Canvas / History Inspector / Runbook  │
│ 窄窗覆盖展开）       │  Studio / 专用工作台                            │
├────────────────────┴───────────────────────────────────────────────┤
│  状态栏：操作状态、当前分支、ahead/behind 与错误反馈                  │
└────────────────────────────────────────────────────────────────────┘
```

标题栏使用原生窗口拖拽与最小化、最大化、关闭控制区；仓库切换按钮展开“功能 / 打开项目 / 最近的项目”三区菜单，支持搜索、键盘导航和关闭已打开仓库。多个仓库通过仓库切换菜单并存管理。

### 2.1 布局特性

| 特性 | 说明 |
|------|------|
| Context Navigator | 唯一左侧列：展开态为「上下文导航」标题 + 模式按钮区（工作区/冲突处理(条件)/提交记录/工作流）+ 引用分组；收起为 48px 窄条（箭头 + 模式图标），任何页面常驻。本地分支可折叠且唯一默认展开 |
| 响应式壳层 | `< 1120px` 为窄窗口，Navigator 收起并由箭头以覆盖层展开，同时隐藏当前分支摘要；`1120–1439px` 为标准布局并停靠；`≥ 1440px` 为舒适布局。titlebar 命令（含“贮藏”“子模块”）在所有宽度常驻内联，不设 overflow；“设置”固定在窗口控制区左侧 |
| 可调分区 | 继续支持各专业画布已有的列宽/高度分割器；导航覆盖层打开或弹窗、菜单出现时不响应分割拖拽 |
| 操作遮罩 | 长时间后台操作时显示项目级操作遮罩（300ms 延迟避免闪烁），阻止误操作 |

### 2.2 主内容区模式 (MainMode)

主内容区根据当前模式展示不同视图，共 **7 种模式**：

| 模式 | 中文名 | 触发条件 | 说明 |
|------|--------|---------|------|
| Worktree | 工作区 | Navigator 模式按钮默认入口 | Review Canvas：变更列表、Diff 和提交区域 |
| Conflict | 冲突处理 | 合并/变基产生冲突时进入，或在冲突入口打开 | 专用三栏冲突工作台：Ours / Result / Theirs，另有可折叠 Base |
| History | 提交记录 | Navigator“提交记录”按钮、快捷键或文件历史入口 | History Inspector：左侧提交导航全高（无泳道、标签最多 1 个），右侧提交详情、文件导航与 Diff 横向检查 |
| CommitGraph | 提交图谱 | 历史页标题栏「图谱」按钮 | 拓扑专注型专用页：泳道列表 + 分支动向高亮 + 搜索 + 轻量详情卡，跳转主历史页无损往返 |
| Workflow | 工作流 | Navigator“工作流”按钮或快捷键 | Runbook Studio：模板导航、运行配置、步骤时间线与 Console |
| Stash | 贮藏 | Context Navigator 贮藏条目，或 titlebar“贮藏”命令（常驻内联） | 贮藏文件列表 + Diff 预览的专用模式 |
| Browse | 浏览 | Context Navigator 分支/标签右键“浏览此分支/标签” | 文件树 + 只读内容/差异；不执行 checkout |
| Blame | 文件追溯 | 工作区/历史文件菜单或 Diff 标题栏“追溯” | 基于 HEAD 与工作区改动的独立追溯视图 |

## 三、应用壳层命令与导航

标题栏不是旧式装饰性命令带，而是 44px 的平面语义色壳层。它从左到右包含品牌、仓库切换、当前分支摘要、常驻命令组、可拖拽空白区和原生窗口控制；当前分支摘要与仓库名过长时截断并悬浮显示完整名称（窄窗口隐藏分支摘要）。

```text
所有宽度：Khaslana  [仓库切换 ▾]  › 当前分支  [刷新][获取][拉取][推送][贮藏][子模块]  [窗口控制]
```

### 3.1 标题栏高频命令

| 命令 | 功能 | 说明 |
|------|------|------|
| 刷新 | 刷新仓库状态 | 重新加载工作区变更和分支信息 |
| 获取 | `git fetch` | 从远端获取最新引用 |
| 拉取 | `git pull` | 拉取并合并远端分支，带 behind 角标 |
| 推送 | `git push` | 推送本地提交，带 ahead 角标 |

### 3.2 仓库切换与标题栏入口

- **仓库切换**：标题栏按钮显示当前仓库头像和名称；下拉菜单提供“克隆仓库…”、“打开仓库…”、“搜索仓库”，并分为“打开项目”和“最近的项目”。
- **克隆/打开**：从仓库切换菜单进入对应对话框，支持原有 URL、路径和递归子模块选项。
- **常驻命令**：刷新/获取/拉取/推送/贮藏/子模块在所有窗口宽度常驻内联于 titlebar，不设 overflow 收纳。“设置”固定在 titlebar 窗口控制区左侧。仓库切换与右键菜单、编码菜单互斥，点击外部关闭。
- **设置**：titlebar 窗口控制区左侧固定“设置”按钮（快捷键 Ctrl+, 等效），打开设置中心。

### 3.3 模式入口（Context Navigator 模式按钮区）

模式按钮位于展开态 Navigator 的「上下文导航」标题与本地分支分组之间；收起态以纯图标形式出现在 48px 窄条中。

| 入口 | 切换到 | 可见条件 |
|------|--------|---------|
| 工作区 | Worktree 模式 | 始终可见 |
| 冲突处理 | Conflict 模式 | 存在冲突时显示 |
| 提交记录 | History 模式 | 始终可见 |
| 工作流 | Workflow 模式 | 始终可见 |

模式入口支持鼠标、稳定焦点的 Tab/Enter/Space 操作和既有快捷键。“贮藏”和“子模块”不占用模式入口：二者常驻内联于 titlebar，任何窗口宽度都可直接触达。

### 3.4 Context Navigator

Context Navigator 是按模式响应式呈现的仓库引用导航，不是旧的全局固定侧栏。它沿用分支、远端、远端分支、标签和贮藏分区及其搜索、折叠、右键菜单能力。

- 展开/收起是跨工作区/提交记录/工作流与所有仓库共享的单一偏好，切换模式或仓库不改变，且持久化保存、重启恢复。
- 标准/舒适宽度停靠在窗口最左侧（收起偏好时为 48px 窄条），可拖拽调整宽度；全部分割线位置（导航宽度、变更列、各页分栏等）同样持久化，重启后保持上次布局。
- 窄窗口隐藏停靠区，由画布边缘按钮展开为覆盖层；覆盖层关闭不改写宽屏停靠偏好。
- Conflict、Stash、Browse、Blame 等专用模式保留完整画布，不显示无意义的 Navigator。
- 分支、远端、标签和贮藏的既有双击、右键、搜索、应用/弹出/丢弃等行为保持不变。

## 五、多仓库并存与仓库切换

应用支持同时打开多个仓库。标题栏的仓库切换按钮打开固定锚定的下拉菜单，菜单按“功能 / 打开项目 / 最近的项目”组织内容。

```
┌──────────────────────────────┐
│ 功能                         │
│   克隆仓库…                  │
│   打开仓库…                  │
│   搜索仓库                  │
├──────────────────────────────┤
│ 打开项目                     │
│   ● project-a           ✕    │
│   project-b             ✕    │
├──────────────────────────────┤
│ 最近的项目                   │
│   project-c                  │
└──────────────────────────────┘
```

| 交互 | 说明 |
|------|------|
| 点击仓库切换项 | 切换到该仓库，独立保留快照、选中分支与历史数据；**保持当前所在主页面**（工作区/提交记录/工作流/提交图谱跟随切换，追溯/浏览等专用页面落回工作区） |
| 关闭按钮 | 关闭已打开的仓库 |
| 搜索仓库 | 实时过滤打开项目和最近的项目，支持名称或完整路径匹配 |
| 键盘导航 | ↑/↓ 环绕移动高亮，Enter 切换/打开，Esc 关闭菜单 |

> 仓库切换菜单与右键菜单和编码菜单互斥；点击菜单外部关闭。

## 六、工作区模式 (Worktree)：Review Canvas

工作区是默认主模式，是日常开发最核心的界面。当前壳层会在它旁边提供 Context Navigator；画布内部采用平面分区，不再依赖旧式顶部/底部工具条。

```
┌──────────────────┬──────────────────────────────────────┐
│ 变更列表          │ Review Canvas                         │
│                  │  工作区标题 + 当前分支                 │
│ 未暂存变更        │  ┌────────── Diff 视图 ─────────────┐ │
│   src/App.tsx    │  │ + import React from 'react';      │ │
│ 已暂存变更        │  │ - import Vue from 'vue';         │ │
│   src/index.ts   │  └───────────────────────────────────┘ │
│                  │  提交区域                              │
│                  │  [提交信息输入框] [AI 生成] [提交]      │
└──────────────────┴──────────────────────────────────────┘
```

Review Canvas 的变更列表和 Diff 继续支持虚拟化、范围选择、按块/按行部分暂存、全文/紧凑、编码切换、语法高亮和长行横向滚动；提交区域继续支持提交、提交并推送、修补提交、修补提交并推送、AI 生成提交信息和合并完成/中止。

### 6.1 变更列表（左侧面板）

分为两个区块：

| 区块 | 说明 |
|------|------|
| 未暂存变更 (Unstaged) | 工作区有改动但未 `git add` 的文件 |
| 已暂存变更 (Staged) | 已 `git add` 但未 `git commit` 的文件 |

**文件行显示**：
- 变更状态标记：`A` 新增（绿色）/ `M` 修改（蓝色）/ `D` 删除（红色）/ `R` 重命名 / `?` 未跟踪（灰色）/ `!` 冲突（红色）
- 文件路径

**交互操作**：

| 操作 | 对未暂存文件 | 对已暂存文件 |
|------|------------|------------|
| 单击 | 选中并显示 Diff | 选中并显示 Diff |
| Shift+点击 | 范围多选 | 范围多选 |
| 右键菜单 | 暂存、丢弃变更、全文/紧凑切换 | 取消暂存 |
| 暂存按钮 | 点击 `+` 暂存单个文件 | 点击 `-` 取消暂存 |
| 暂存全部 | 区块头部的 `+` 按钮 | 区块头部的 `-` 按钮 |
| 丢弃全部 | 区块头部的垃圾桶按钮 | — |

### 6.2 Diff 视图（右侧面板）

展示选中文件的变更详情。

**Diff 行样式**：
| 行类型 | 背景 | 说明 |
|--------|------|------|
| 上下文行 | 默认背景 | 未修改的参考行 |
| 新增行 | 浅绿背景 | `+` 前缀 |
| 删除行 | 浅红背景 | `-` 前缀 |
| 文件头 | 浅蓝背景 | 文件路径标题行 |

**Diff 功能**：

| 功能 | 说明 |
|------|------|
| 全文/紧凑切换 | 全文模式显示完整文件内容（含未修改行），紧凑模式仅显示变更上下文 |
| 编码切换 | 自动检测 UTF-8/GB18030/Big5，可手动切换编码 |
| 行号显示 | 左侧显示旧/新行号 |
| Diff 头折叠 | 多个文件同时暂存时，每个文件的 diff 头可折叠 |

**多文件 Diff**：选中多个文件时，按顺序纵向堆叠显示各文件 Diff。

### 6.3 提交区域（变更列表底部）

| 元素 | 说明 |
|------|------|
| 提交信息输入框 | 多行文本输入，支持 IME 中文输入 |
| AI 生成按钮 | 调用 AI 根据暂存区 Diff 自动生成提交信息（流式实时显示） |
| 提交按钮 | 执行 `git commit`，提交信息为空时禁用 |

**AI 生成 Commit Message 流程**：
1. 点击"AI 生成"按钮
2. 系统收集所有暂存文件的 Diff 文本
3. 流式调用 Chat Completions API
4. 实时逐字填充提交信息输入框
5. 生成完毕后用户可编辑或直接提交

## 七、冲突处理模式 (Conflict)

当合并或变基产生冲突时，自动切入此模式。

```
┌────────────┬─┬───────────────────────────────────────────────┐
│  冲突文件   │↕│  三栏冲突工作台                                │
│  列表      │ │                                               │
│            │ │ ┌── Ours ──┐ ┌── Result ──┐ ┌── Theirs ──┐  │
│ ● App.tsx  │ │ │ 我们的内容 │ │  合并结果   │ │  他们的内容 │  │
│ ● util.ts  │ │ │           │ │            │ │            │  │
│            │ │ └──────────┘ └────────────┘ └────────────┘  │
│            │ │  ▼ Base（可折叠：共同祖先内容）                  │
│            │ │                                               │
│            │ │  冲突块: [采用 Ours] [采用 Theirs] [忽略]       │
├────────────┴─┼───────────────────────────────────────────────┤
│              │  [全部标记已解决]             [提交解决]         │
└──────────────┴───────────────────────────────────────────────┘
```

### 7.1 冲突文件列表（左侧）

- 显示所有冲突文件，带冲突图标
- 点击文件加载其冲突详情

### 7.2 三栏冲突工作台（右侧）

| 栏 | 说明 |
|----|------|
| Ours（我们的） | 当前分支的内容 |
| Result（结果） | 合并后的草稿，可手动编辑 |
| Theirs（他们的） | 要合并进来的内容 |
| Base（基础） | 共同祖先内容，默认折叠 |

**冲突块操作**：
- 每个冲突块显示边界标记
- 可逐块选择：采用 Ours / 采用 Theirs / 忽略此块 / 同时保留（Ours优先 / Theirs优先）
- 手动编辑 Result 栏内容
- 块状态标记：未解决(警告色) / 已解决或已合并(成功色) / 已忽略(灰)

### 7.3 底部操作

| 按钮 | 说明 |
|------|------|
| 全部标记已解决 | 将所有冲突块标记为已解决 |
| 提交解决 | 执行 `git commit` 完成冲突解决 |
| 变基操作条 | 变基冲突时额外显示：继续/跳过/中止 |

## 八、提交记录模式 (History)：History Inspector

History Inspector 横向组织提交历史与提交检查：左侧提交导航贯穿全高，右侧按上下两层展示提交详情和文件/差异检查，提交列表与检查内容始终保持可见。主历史页负责「解剖单个提交」；泳道拓扑与分支动向整体放在提交图谱页（见 8.4），标题栏「图谱」按钮进入。

```
┌──────────────────┬─────────────────────────────────────────────┐
│ 提交导航（全高）  │ 提交详情（可折叠/可滚动）                    │
│                  │ 摘要 · 完整信息 · SHA · 作者 · 父提交         │
│ ● abc1234 feat [main] ├─────────────────────────────────────────┤
│   Alice · 2 小时前     │ 提交文件（窄栏） │      Diff 视图             │
│ │ ● def5678 fix       │ App.tsx          │ + import { Login } ...    │
│ │   Bob · 昨天         │ util.ts          │ - import { Old } ...      │
└──────────────────┴─────────────────────────────────────────────┘
```

提交导航支持分页加载、当前分支/所有引用范围、文件路径过滤和引用标签；导航行不画泳道，行内引用标签最多 1 个（HEAD/首个本地分支优先，其余收进「+n」徽标悬浮查看），避免窄列里标签遮挡提交摘要。每条提交固定使用专用 48px 两行布局，第一行显示摘要/ref，第二行显示作者/avatar，避免头像和引用徽标被裁切。该布局仅适用于 History 提交行，全局常规列表行仍为 36px。右侧详情保留完整提交信息、作者/提交者、时间、父提交、复制 SHA/信息、文件列表和完整文件 Diff。详情高度和文件导航宽度可按现有分割器调整，双击可复位。

### 8.1 提交导航（左侧，全高）

| 显示信息 | 说明 |
|---------|------|
| SHA | 短哈希（7 位） |
| 提交摘要 | 第一行提交信息 |
| 引用标签 | 最多 1 个（分支名(蓝)/远端分支名(紫)/标签名(黄)/HEAD(红)，HEAD 优先），其余「+n」悬浮查看 |
| 作者 | 提交者名称 |
| 时间 | 相对时间（如"2小时前"） |
| 未推送标记 | 领先 upstream 的提交左侧显示黄色竖条 |

**交互操作**：

| 操作 | 说明 |
|------|------|
| 点击提交 | History Inspector 右侧下层加载该提交的文件变更列表 |
| 右键菜单 | 检出此提交、Reset 到此提交、Revert 此提交 |
| 滚动加载 | 向下滚动自动加载更多提交 |
| 历史范围 | 切换"当前分支"或"所有引用" |
| 图谱 | 跳转到提交图谱页（泳道拓扑、分支动向高亮、搜索） |

### 8.2 提交文件导航（右侧下层左栏）

- 显示选中提交涉及的文件变更
- 每行显示：变更状态标记 + 文件路径
- 点击文件加载该文件的 Diff

### 8.3 Diff 视图（右侧下层右栏）

- 与工作区模式的 Diff 视图功能一致
- 额外支持：查看某个提交的完整文件 Diff

### 8.4 提交图谱页（Commit Graph，专用模式）

拓扑专注型独立页面：主历史页负责解剖单个提交，图谱页负责看提交之间的关系。与主历史页共享同一份提交列表、范围切换、分页与选中提交；跳转往返无损（高亮、开关、搜索词、滚动位置完整保留）。

```
┌───────────────────────────────────────────────────────────────┐
│ 提交图谱                                        [Scope] [关闭] │
│ [当前分支|所有分支] [分支高亮 ▾] [仅领先HEAD] [淡化合并] [搜索] │
│ │ ● feat-2 ○ 淡化的其他分支提交                                │
│ │ ● feat-1 高亮谱系内的提交保持全彩                            │
│ │ └● base …                                                   │
├───────────────────────────────────────────────────────────────┤
│ 提交详情 · 完整信息/作者/父提交/全量标签 [在提交记录页查看]     │
└───────────────────────────────────────────────────────────────┘
```

- **泳道拓扑**：全高泳道列表（8 色循环），泳道列宽可拖拽（双击复位），可见泳道数随列宽变化、超出以省略号提示；行内引用标签最多 3 个 + 「+n」悬浮。
- **分支动向高亮**：下拉选择本地分支后，谱系内提交保持正常、谱系外行淡化（泳道线与行内容降透明度），一眼看清该分支的动向；支持「全谱系」与「仅领先 HEAD」两档；谱系上限 2000 个提交（截断时提示）；操作移动分支 tip 后自动重算。
- **淡化合并提交**：独立开关，把多父提交的点与连线淡化，让分支主干更清爽。
- **搜索过滤**：按提交摘要/作者/短 SHA 子串（大小写不敏感）过滤已加载提交，可配合「加载更多」扩大范围；搜索或文件过滤激活时泳道自动隐藏（避免断线）。
- **轻量详情卡**：选中提交的完整信息、作者/提交者、时间、父提交、全量引用标签与复制 SHA；「在提交记录页查看」跳回主历史页，四象限直接就位（文件/差异已预加载），再点「图谱」按钮无损返回。

## 九、工作流模式 (Workflow)：Runbook Studio

Runbook Studio 执行 JSON5 定义的自动化 Git 工作流。它采用模板导航 + 工作流详情画布 + 可展开 Console 的工作台结构，运行配置按输入定义显示并与步骤时间线并列。

```
┌──────────────────┬─────────────────────────────────────────────┐
│ 模板导航          │ Runbook Studio                              │
│ [刷新] [目录]     │ [模板名称 / 文件] [状态] [运行]             │
│ ● 发布流程        ├──────────────────┬──────────────────────────┤
│ ● 热修复          │ 运行配置          │ 步骤时间线                │
│                  │ 版本号 [v1.2.0]  │ 1 Checkout → main         │
│                  │ 环境   [production]│ 2 Fetch origin           │
│                  │（有输入时显示）    │ 3 Pull / Push ...         │
│                  ├──────────────────┴──────────────────────────┤
│                  │ Console：运行状态、逐步日志与结果摘要        │
└──────────────────┴─────────────────────────────────────────────┘
```

无输入参数时，步骤时间线占据详情主区；选择模板文件后立即加载定义并生成预览，外部 JSON5/JSONC 文件也可直接选择。

### 9.1 模板导航（左侧）

- 从当前激活数据目录的 `workflows/` 加载 JSON5 / JSONC 模板；旧 `~/.khaslana/workflows/` 仅在新目录为空时一次性迁移
- 点击模板加载其定义和输入参数

### 9.2 Runbook Studio 详情画布

| 区域 | 说明 |
|------|------|
| Studio 标题区 | 显示工作流名称、文件路径和“未选择/已就绪/运行中/需要修正”状态 |
| 运行配置 | 有输入参数时显示动态输入、必填标记和默认值；无输入时不占用主区 |
| 步骤时间线 | 展示解析变量后的每一步 Git 操作及补充详情 |
| Console | 默认折叠；运行中或已有日志时展开，显示逐步进度、失败信息和结果摘要 |
| 操作命令 | “运行”；模板列表提供刷新和打开目录 |

### 9.3 工作流步骤类型

| 步骤 | 说明 |
|------|------|
| Checkout | 切换到指定分支 |
| Fetch | 获取远端更新 |
| Pull | 拉取远端分支 |
| CreateBranch | 创建新分支 |
| Merge | 合并分支 |
| Push | 推送到远端 |
| GuardRemoteBranch | 检查远端分支存在性（存在/不存在时的策略） |
| EnsureClean | 确保工作区干净 |
| AssertBranch | 断言当前分支 |

### 9.4 执行状态

- 执行时显示进度条和当前步骤
- 每步完成/失败实时更新
- 执行完毕显示结果摘要

## 十一、浏览模式 (Browse)

只读浏览某分支或标签的文件内容，无需 checkout。

```
┌────────────┬─┬──────────────────────────────────────┐
│  文件树     │↕│  内容 / Diff 视图                     │
│            │ │                                      │
│ ▼ src/     │ │  // 文件只读内容                       │
│   App.tsx  │ │  import React from 'react';          │
│   util.ts  │ │                                      │
│ ▼ docs/    │ │  或                                  │
│   README.md│ │                                      │
│            │ │  // 与当前 HEAD 的差异                  │
└────────────┴─┴──────────────────────────────────────┘
```

### 11.1 文件树（左侧）

- 懒加载目录结构（点击目录展开子项）
- 支持两种子模式：
  - **树模式 (Tree)**：浏览分支的完整文件树
  - **对比模式 (Compare)**：仅显示与当前 HEAD 有差异的文件

### 11.2 内容/Diff 视图（右侧）

| 子模式 | 说明 |
|--------|------|
| Content | 只读显示文件内容（语法高亮） |
| Diff | 显示该文件与当前 HEAD 的差异 |

**AI Code Review**：在对比模式的内容画布中可展开 AI 评审面板，对比较列表中的全部差异文件进行 AI 代码评审；面板展开时占满右侧区域，收起时回到底部条。

### 11.3 文件追溯模式 (Blame)

文件追溯是独立的专用模式，不占用工作区的 Diff 画布。入口包括工作区变更右键、历史页提交文件右键，以及工作区 Diff 标题栏的“追溯”按钮；历史入口追溯 HEAD 版本，工作区入口纳入当前工作区未提交改动。

```
┌──────────────────────────────────────────────────────────────┐
│ 文件追溯  path/to/file.rs                 [编码] [关闭]       │
├───────────────┬────────┬─────────────────────────────────────┤
│ 提交归属注释栏  │ 行号   │ 内容（已提交行语法高亮）             │
│ abc123 作者... │   1    │ fn main() {                          │
│                │   2    │     ...                              │
│ 未提交          │   3    │ changed line                         │
└───────────────┴────────┴─────────────────────────────────────┘
```

- 三列为注释栏、行号、内容；注释栏使用微灰侧栏区分代码区，不绘制贯穿页面的分割线。
- 连续同源行只在块首行显示提交哈希、作者、日期和摘要；悬浮可查看完整提交信息。
- 工作区未提交行整行使用警告色和“未提交”标记，不做语法高亮；已提交行使用统一语法高亮。
- 支持虚拟列表、双向滚动和编码切换；HEAD 缺少文件、二进制文件或过大文件时给出中文错误。

## 十三、AI 功能

### 13.1 AI 设置中心分类

从设置中心的“AI 设置”分类配置供应商，右侧内容区包含以下配置项：

| 字段 | 类型 | 说明 |
|------|------|------|
| 启用 AI | 开关 | 总开关，关闭后所有 AI 功能不可用 |
| 接口类型 | 只读显示 | 当前固定为 "Chat Completions"（OpenAI 兼容） |
| Base URL | 文本输入 | API 基础地址（如 `https://api.openai.com/v1`） |
| API Key | 文本输入 | 密钥（可选，本地模型如 Ollama 不需要） |
| Model | 文本输入 | 模型名称（如 `gpt-4o`、`deepseek-chat`） |

**辅助信息**：
- 提示 API Key 可选、明文保存
- 测试连接按钮：发送最小请求验证 API 可用性
- “保存”按钮；关闭设置中心使用右上角“×”、背景点击或 Esc

### 13.2 AI 生成 Commit Message

**入口**：工作区模式提交区域的"AI 生成"按钮

**流程**：
1. 系统收集所有已暂存文件的 Diff 文本（截断上限 6000 字符）
2. 构造中文 Conventional Commits 风格的 Prompt
3. 流式调用 Chat Completions API
4. 实时逐字填充提交信息输入框
5. 生成完毕后用户可编辑或直接提交

**触发条件**：
- 存在已暂存的文件
- AI 设置已配置且可用
- 当前没有正在生成的任务

### 13.3 AI Code Review

**入口**：浏览模式 → 对比模式 → 内容画布中的“AI 评审”面板

**流程**：
1. 系统收集当前文件与 HEAD 的 Diff 文本（截断上限 8000 字符）
2. 构造中文评审 Prompt（按严重问题/建议/风险点/优点分组）
3. 流式调用 Chat Completions API
4. 在评审面板中实时显示评审结果
5. 可折叠展开思考链 (Reasoning) 内容

**评审面板**：
- 位于 Browse 对比模式的内容画布中；展开时占满右侧区域，替换内容/差异视图
- 收起时回到底部单行条，显示进度或正文预览；生成中仍可展开或取消
- 生成中实时显示思维链、工具调用轨迹和正文；完成后显示 Markdown 正文
- 支持历史记录弹窗、复制结论、重新生成和流式增量显示
- 切换比较目标或退出浏览只分离当前展示，后台任务继续至完成并落盘；取消在轮次边界生效

### 13.4 AI 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| temperature | 0.3 | 生成随机性 |
| max_tokens | 8192（AI 评审） | 输出 token 上限；评审思考链与正文共用预算 |
| request_timeout_secs | 60 | 请求超时时间 |
| 流式模式 | 开启 | commit/review 默认使用 SSE 流式 |

## 十四、设置中心的网络代理分类

从设置中心的“网络代理”分类配置代理，包含三种模式选择：

| 模式 | 说明 |
|------|------|
| 不使用代理 | 直连网络 |
| 使用系统代理 | 读取操作系统代理设置 |

## 十七、核心交互流程

### 17.1 打开仓库

```
点击"打开仓库" → 系统文件对话框 → 选择目录 → 后台加载仓库
  → 加载成功: Context Navigator 显示分支/远端、Review Canvas 显示变更
  → 加载失败: 显示错误反馈气泡
```

### 17.2 提交代码 (Commit)

```
工作区模式:
  1. 查看未暂存变更 → 点击 "+" 暂存文件
  2. 右侧查看暂存文件的 Diff
  3. 底部输入提交信息（或点击"AI 生成"）
  4. 点击"提交" → 成功后工作区清空
```

### 17.3 分支切换

```
Context Navigator 双击分支 → 后台执行 checkout
  → 成功: 刷新工作区变更和分支状态
  → 冲突: 自动切换到 Conflict 模式
```

### 17.4 拉取/推送

```
标题栏点击“拉取/推送” → 弹出远端分支操作对话框
  → 选择远端和分支 → 执行
  → 需要凭据: 弹出凭据输入对话框
  → 成功: 刷新状态 + 显示成功通知
```

### 17.5 冲突解决

```
合并/变基产生冲突 → 自动切入 Conflict 模式
  1. 左侧选择冲突文件
  2. 三栏工作台逐块选择 Ours/Theirs
  3. 全部解决后点击"提交解决"
  → 变基冲突: 底部额外显示"继续/跳过/中止"
```

### 17.6 AI 辅助工作流

```
AI Commit:
  1. 暂存文件 → 点击"AI 生成" → 流式生成提交信息 → 编辑/提交

AI Code Review:
  1. 浏览模式 → 切换到对比模式 → 选择文件
  2. 在内容画布中展开“AI 评审”面板（可占满右侧区域，也可收起到底部条）
  3. 流式生成评审结果 → 查看正文、思考链和工具轨迹
```

### 17.7 工作流执行

```
Navigator 模式按钮进入工作流 → 选择模板 → 填写运行配置（如有）→ 查看步骤时间线 → 运行
  → 每步实时显示进度
  → 步骤失败: 停止执行 + 显示错误
  → 全部完成: 显示结果摘要
```

## 十八、设计体系概述

### 18.1 视觉风格：Calm Technical

Focus Workbench 使用“Calm Technical”风格：保持 Git 工作所需的信息密度，以稳定层级、平面表面和清晰反馈降低装饰竞争。

| 特征 | 说明 |
|------|------|
| 应用壳层 | 44px 自定义标题栏 + Context Navigator（模式按钮 + 引用分组，收起为 48px 窄条） |
| 页面表面 | 平面语义色 surface；默认页面、列表和导航不使用渐变或装饰阴影 |
| 浮层 | 菜单、对话框、Toast 和遮罩使用明确的浮层层级与必要阴影 |
| 弹窗面板 | 语义色面板 + 半透明遮罩，危险操作使用 Danger Callout |
| 分支图 | 8 色循环色（彩色拓扑线） |
| 引用标签 | 分支=蓝、远端=紫、标签=黄、HEAD=红 |
| 可访问性 | 稳定焦点句柄、Tab/Enter/Space、禁用原因提示和主题色焦点环 |

### 18.2 色彩系统分类

| 分类 | 典型 Token | 用途 |
|------|-----------|------|
| Surface | `SURFACE_CANVAS`, `SURFACE_BASE`, `SURFACE_RAISED`, `SURFACE_SUNKEN`, `SURFACE_OVERLAY` | 画布、面板、输入和浮层底色 |

| 危险/状态 | `DESTRUCTIVE`, `FEEDBACK_*` | 危险、成功、警告、错误和信息反馈 |

## 二十、数据持久化

所有配置数据存储在 SQLite 数据库 (`khaslana.sqlite3`) 中：

| 数据表 | 内容 |
|--------|------|
| session_state | 上次打开的仓库路径、激活仓库 |
| session_repositories | 仓库路径列表 |
| diff_encoding_preferences | 每个仓库的 diff 编码偏好 |
| network_proxy_settings | 全局代理设置 |
| remote_credential_bindings | 远端→凭据策略绑定 |
| credential_records | 凭据记录索引（密钥本体在系统 Keyring） |
| ai_provider_settings | AI 供应商配置 |

> **凭据安全**：密码/密钥等敏感信息存储在操作系统原生 Keyring 中，SQLite 仅存储索引和元数据。

## 二十一、现有架构特征（供重构参考）

> 以下为技术架构特征，供 UI/产品团队在规划重构时理解现有约束和可优化方向。

| 特征 | 现状 | 重构关注点 |

| 任务调度 | 双线程池（短任务 2-4 线程 + 长任务 2 线程） | 架构合理，可复用 |
| 代理统一 | Git + AI 共用代理策略 | 可保持 |
