# Khaslana 产品文档

> **版本**：v4（当前线上版本）
> **定位**：桌面端 Git 客户端，面向开发者提供仓库管理、版本控制、代码评审等全流程工具
> **技术栈**：Rust + GPUI（GPU 加速原生 UI）+ libgit2
> **平台**：Windows / macOS / Linux

---

## 一、产品概述

Khaslana 是一款原生桌面 Git 客户端，以中文为主要界面语言。核心能力包括：

| 能力域 | 说明 |
|--------|------|
| 仓库管理 | 打开本地仓库、克隆远端仓库、多仓库标签切换 |
| 版本控制 | 暂存/提交/推送/拉取/获取/分支切换/合并/变基/回滚 |
| 代码浏览 | 提交历史查看、分支浏览、文件对比（Diff） |
| 冲突解决 | 三栏冲突工作台，块级选择 Ours/Theirs |
| AI 辅助 | AI 生成 Commit Message、AI Code Review |
| 工作流引擎 | JSON5 定义自动化流程，支持变量插值与远端守卫 |
| 凭据管理 | HTTPS/SSH 凭据存储（系统 Keyring），远端凭据绑定 |
| 网络代理 | 不使用/系统代理/自定义代理三种模式 |

## 二、全局布局

应用整体为**垂直列式布局**，从上到下依次为：

```
┌──────────────────────────────────────────────────────────┐
│  工具栏 (Toolbar)                                         │
├──────────────────────────────────────────────────────────┤
│  多仓库标签栏 (Tab Bar)                                    │
├──────────┬─┬─────────────────────────────────────────────┤
│          │ │                                             │
│  侧边栏  │↕│  主内容区 (按模式切换)                        │
│ (Sidebar)│ │                                             │
│          │ │                                             │
├──────────┴─┴─────────────────────────────────────────────┤
│  状态栏 (Status Bar)                                      │
└──────────────────────────────────────────────────────────┘

↕ = 可拖拽分割器 (Resize Splitter)
```

### 2.1 布局特性

| 特性 | 说明 |
|------|------|
| 多仓库标签 | 支持同时打开多个仓库，标签栏可水平滚动 |
| 可调分区 | 6 个可拖拽分割器控制各区域宽度/高度 |
| 响应式工具栏 | 窄窗口时部分按钮折叠到"更多"溢出菜单（全量布局最小宽度 1540px） |
| 操作遮罩 | 长时间后台操作时显示半透明遮罩（300ms 延迟避免闪烁），阻止误操作 |

### 2.2 主内容区模式 (MainMode)

主内容区根据当前模式展示不同视图，共 **6 种模式**：

| 模式 | 中文名 | 触发条件 | 说明 |
|------|--------|---------|------|
| Worktree | 工作区 | 默认模式 | 左侧变更列表 + 右侧 Diff + 底部提交 |
| Conflict | 冲突处理 | 合并/变基产生冲突时自动切入 | 冲突文件列表 + 三栏冲突工作台 |
| History | 提交记录 | 点击工具栏"历史"按钮 | 上方提交列表 + 下方文件变更/Diff |
| Workflow | 工作流 | 点击工具栏"工作流"按钮 | 模板选择 + 参数填写 + 执行 |
| Stash | 贮藏 | 点击工具栏"贮藏"按钮 | 贮藏文件列表 + Diff 预览 |
| Browse | 浏览 | 侧边栏右键分支→"浏览此分支" | 文件树 + 只读内容/差异 |

## 三、工具栏 (Toolbar)

工具栏位于应用顶部，采用**毛玻璃**效果，分为左、中、右三个区域。

```
┌──────────────────────────────────────────────────────────────────┐
│ [打开][克隆][刷新][获取][拉取][推送][贮藏][子模块][凭据][代理][AI]  仓库路径  [工作区][冲突?][历史][工作流] │
│  ← 左侧操作按钮                                                   中间               右侧模式切换 →  │
└──────────────────────────────────────────────────────────────────┘
```

### 3.1 左侧操作按钮

| 按钮 | 图标 | 功能 | 说明 |
|------|------|------|------|
| 打开仓库 | 📂 | 打开本地 Git 仓库 | 弹出系统文件选择对话框 |
| 克隆仓库 | ⬇️ | 克隆远端仓库 | 弹出克隆对话框 |
| 刷新 | 🔄 | 刷新仓库状态 | 重新加载工作区变更和分支信息 |
| 获取 | ⬇️ | git fetch | 从远端获取最新引用 |
| 拉取 | ⬇️⬆️ | git pull | 拉取并合并远端分支（带 ahead/behind 角标） |
| 推送 | ⬆️ | git push | 推送本地提交到远端（带未推送数角标） |
| 贮藏 | 📦 | git stash | 切换到贮藏模式 |
| 子模块 | 🔗 | 子模块管理 | 打开子模块管理对话框 |
| 凭据管理 | 🔑 | 管理凭据记录 | 打开凭据管理器对话框 |
| 代理设置 | 🌐 | 网络代理配置 | 打开代理设置对话框 |
| AI 设置 | 🤖 | AI 供应商配置 | 打开 AI 设置对话框 |

> **响应式行为**：窄窗口时，部分按钮折叠到"更多(⋯)"溢出菜单中（宽度 190px，高度 156px）。

### 3.2 中间区域

- **仓库路径徽标 (Pill)**：显示当前仓库路径，点击可打开系统文件管理器

### 3.3 右侧模式切换

| 按钮 | 切换到 | 可见条件 |
|------|--------|---------|
| 工作区 | Worktree 模式 | 始终可见 |
| 冲突处理 | Conflict 模式 | 仅存在冲突时可见 |
| 提交记录 | History 模式 | 始终可见 |
| 工作流 | Workflow 模式 | 始终可见 |

## 四、侧边栏 (Sidebar)

侧边栏位于主内容区左侧，宽度可拖拽调整，包含 **5 个可折叠分区**：

```
┌──────────────────┐
│ ▼ 本地分支    🔍+ │  ← 默认展开，带搜索和创建按钮
│   main          * │  ← * 表示 HEAD 所在分支
│   feature/login   │
│   fix/bug-123     │
├──────────────────┤
│ ▼ 远端        管理 │  ← 默认展开，带"管理"按钮
│   origin          │
│   upstream        │
├──────────────────┤
│ ▶ 远端分支     🔍 │  ← 默认折叠，带搜索
├──────────────────┤
│ ▶ 标签            │  ← 仅有标签时显示，默认折叠
├──────────────────┤
│ ▶ 贮藏            │  ← 仅有贮藏时显示，默认折叠
└──────────────────┘
```

### 4.1 本地分支区

| 交互 | 说明 |
|------|------|
| 双击分支 | 切换到该分支（checkout） |
| 右键菜单 | 浏览此分支、重命名、删除、设置上游、拉取、推送 |
| 搜索 | 按名称过滤分支列表 |
| 创建按钮 (+) | 弹出"创建分支"对话框 |

**分支行显示**：
- 分支名称
- HEAD 标记（`*` 图标）表示当前所在分支
- 上游信息（如 `→origin/main`）

### 4.2 远端区

| 交互 | 说明 |
|------|------|
| 点击远端 | 展开/折叠其下的远端分支 |
| 右键菜单 | 添加远端、编辑远端、删除远端 |
| 管理按钮 | 打开远端管理对话框 |

**远端行显示**：远端名称 + URL

### 4.3 远端分支区

| 交互 | 说明 |
|------|------|
| 双击分支 | 检出为本地分支 |
| 右键菜单 | 浏览此分支、检出为本地分支、删除远端分支 |
| 搜索 | 按名称过滤 |

### 4.4 标签区

| 交互 | 说明 |
|------|------|
| 双击标签 | 检出该标签 |
| 右键菜单 | 浏览此标签 |

### 4.5 贮藏区

| 交互 | 说明 |
|------|------|
| 点击贮藏 | 切换到 Stash 模式预览该贮藏 |
| 右键菜单 | 应用贮藏、弹出贮藏、丢弃贮藏 |

## 五、多仓库标签栏 (Tab Bar)

位于工具栏下方，水平排列，支持同时打开多个仓库。

```
┌────────────┬────────────┬────────────┐
│ ● project-a │  project-b  │     +      │
└────────────┴────────────┴────────────┘
  ← 活跃标签（高亮）   ← 可点击切换   ← 打开新仓库
```

| 交互 | 说明 |
|------|------|
| 点击标签 | 切换到该仓库（整体状态独立切换） |

## 六、工作区模式 (Worktree)

工作区是默认主模式，是日常开发最核心的界面。

```
┌────────────┬─┬──────────────────────────────────────┐
│  变更列表   │↕│          Diff 视图                    │
│            │ │                                      │
│ 未暂存变更  │ │  + import React from 'react';        │
│  └ src/    │ │  - import Vue from 'vue';            │
│    App.tsx │ │  + import './style.css';             │
│    util.ts │ │                                      │
│ 已暂存变更  │ │                                      │
│  └ src/    │ │                                      │
│    index.ts│ │                                      │
├────────────┴─┼──────────────────────────────────────┤
│              │  提交信息输入框                         │
│              │  ┌──────────────────────────────────┐ │
│              │  │ feat: add React migration        │ │
│              │  │                                  │ │
│              │  └──────────────────────────────────┘ │
│              │  [🤖 AI 生成]            [提交]        │
└──────────────┴──────────────────────────────────────┘
```

### 6.1 变更列表（左侧面板）

分为两个区块：

| 区块 | 说明 |
|------|------|
| 未暂存变更 (Unstaged) | 工作区有改动但未 `git add` 的文件 |
| 已暂存变更 (Staged) | 已 `git add` 但未 `git commit` 的文件 |

**文件行显示**：
- 变更状态标记：`A` 新增（绿色）/ `M` 修改（蓝色）/ `D` 删除（红色）/ `R` 重命名 / `?` 未跟踪（灰色）/ `!` 冲突（红色）
- 文件路径

**交互操作**：

| 操作 | 对未暂存文件 | 对已暂存文件 |
|------|------------|------------|
| 单击 | 选中并显示 Diff | 选中并显示 Diff |
| Shift+点击 | 范围多选 | 范围多选 |
| 右键菜单 | 暂存、丢弃变更、全文/紧凑切换 | 取消暂存 |
| 暂存按钮 | 点击 `+` 暂存单个文件 | 点击 `-` 取消暂存 |
| 暂存全部 | 区块头部的 `+` 按钮 | 区块头部的 `-` 按钮 |
| 丢弃全部 | 区块头部的垃圾桶按钮 | — |

### 6.2 Diff 视图（右侧面板）

展示选中文件的变更详情。

**Diff 行样式**：
| 行类型 | 背景 | 说明 |
|--------|------|------|
| 上下文行 | 默认背景 | 未修改的参考行 |
| 新增行 | 浅绿背景 | `+` 前缀 |
| 删除行 | 浅红背景 | `-` 前缀 |
| 文件头 | 浅蓝背景 | 文件路径标题行 |

**Diff 功能**：

| 功能 | 说明 |
|------|------|
| 全文/紧凑切换 | 全文模式显示完整文件内容（含未修改行），紧凑模式仅显示变更上下文 |
| 编码切换 | 自动检测 UTF-8/GB18030/Big5，可手动切换编码 |
| 行号显示 | 左侧显示旧/新行号 |
| Diff 头折叠 | 多个文件同时暂存时，每个文件的 diff 头可折叠 |

**多文件 Diff**：选中多个文件时，按顺序纵向堆叠显示各文件 Diff。

### 6.3 提交区域（右下角）

| 元素 | 说明 |
|------|------|
| 提交信息输入框 | 多行文本输入，支持 IME 中文输入 |
| AI 生成按钮 | 调用 AI 根据暂存区 Diff 自动生成提交信息（流式实时显示） |
| 提交按钮 | 执行 `git commit`，提交信息为空时禁用 |

**AI 生成 Commit Message 流程**：
1. 点击"AI 生成"按钮
2. 系统收集所有暂存文件的 Diff 文本
3. 流式调用 Chat Completions API
4. 实时逐字填充提交信息输入框
5. 生成完毕后用户可编辑或直接提交

## 七、冲突处理模式 (Conflict)

当合并或变基产生冲突时，自动切入此模式。

```
┌────────────┬─┬───────────────────────────────────────────────┐
│  冲突文件   │↕│  三栏冲突工作台                                │
│  列表      │ │                                               │
│            │ │ ┌── Ours ──┐ ┌── Result ──┐ ┌── Theirs ──┐  │
│ ● App.tsx  │ │ │ 我们的内容 │ │  合并结果   │ │  他们的内容 │  │
│ ● util.ts  │ │ │           │ │            │ │            │  │
│            │ │ └──────────┘ └────────────┘ └────────────┘  │
│            │ │  ▼ Base（可折叠：共同祖先内容）                  │
│            │ │                                               │
│            │ │  冲突块: [采用 Ours] [采用 Theirs] [忽略]       │
├────────────┴─┼───────────────────────────────────────────────┤
│              │  [全部标记已解决]             [提交解决]         │
└──────────────┴───────────────────────────────────────────────┘
```

### 7.1 冲突文件列表（左侧）

- 显示所有冲突文件，带冲突图标
- 点击文件加载其冲突详情

### 7.2 三栏冲突工作台（右侧）

| 栏 | 说明 |
|----|------|
| Ours（我们的） | 当前分支的内容 |
| Result（结果） | 合并后的草稿，可手动编辑 |
| Theirs（他们的） | 要合并进来的内容 |
| Base（基础） | 共同祖先内容，默认折叠 |

**冲突块操作**：
- 每个冲突块显示边界标记
- 可逐块选择：采用 Ours / 采用 Theirs / 忽略此块 / 同时保留（Ours优先 / Theirs优先）
- 手动编辑 Result 栏内容
- 块状态标记：未解决(红) / 已解决(绿) / 已忽略(灰)

### 7.3 底部操作

| 按钮 | 说明 |
|------|------|
| 全部标记已解决 | 将所有冲突块标记为已解决 |
| 提交解决 | 执行 `git commit` 完成冲突解决 |
| 变基操作条 | 变基冲突时额外显示：继续/跳过/中止 |

## 八、提交记录模式 (History)

查看提交历史、浏览每个提交的文件变更和 Diff。

```
┌──────────────────────────────────────┐
│  提交列表（带分支图）                   │
│  ● abc1234 feat: add login     main  │  ← 提交行：SHA + 摘要 + 引用标签
│  │ ● def5678 fix: resolve bug        │
│  │ │ ● ghi9012 chore: cleanup       │
│  ● jkl3456 feat: initial commit      │
├──────────┬─┬─────────────────────────┤
│ 文件变更  │↕│       Diff 视图          │
│ 列表     │ │                         │
│ App.tsx  │ │  + import { Login } ... │
│ util.ts  │ │  - import { Old } ...   │
└──────────┴─┴─────────────────────────┘
```

### 8.1 提交列表（上方）

| 显示信息 | 说明 |
|---------|------|
| 提交图 | 左侧彩色分支线（8 色循环）表示分支拓扑 |
| SHA | 短哈希（7 位） |
| 提交摘要 | 第一行提交信息 |
| 引用标签 | 分支名(蓝)/远端分支名(紫)/标签名(黄)/HEAD(红) |
| 作者 | 提交者名称 |
| 时间 | 相对时间（如"2小时前"） |

**交互操作**：

| 操作 | 说明 |
|------|------|
| 点击提交 | 下方加载该提交的文件变更列表 |
| 右键菜单 | 检出此提交、Reset 到此提交、Revert 此提交 |
| 滚动加载 | 向下滚动自动加载更多提交 |
| 历史范围 | 切换"当前分支"或"所有引用" |

### 8.2 文件变更列表（左下）

- 显示选中提交涉及的文件变更
- 每行显示：变更状态标记 + 文件路径
- 点击文件加载该文件的 Diff

### 8.3 Diff 视图（右下）

- 与工作区模式的 Diff 视图功能一致
- 额外支持：查看某个提交的完整文件 Diff

## 九、工作流模式 (Workflow)

执行 JSON5 定义的自动化 Git 工作流。

```
┌────────────┬─┬──────────────────────────────────────┐
│  工作流模板  │↕│  工作流详情                           │
│  列表      │ │                                      │
│            │ │  模板名称: 发布流程                     │
│ ● 发布流程  │ │                                      │
│ ● 热修复    │ │  输入参数:                            │
│            │ │  ┌──────────────────────────────────┐ │
│            │ │  │ 版本号: [v1.2.0            ]      │ │
│            │ │  │ 环境:   [production       ]      │ │
│            │ │  └──────────────────────────────────┘ │
│            │ │                                      │
│            │ │  步骤预览:                            │
│            │ │  1. Checkout → main                  │
│            │ │  2. Fetch origin                     │
│            │ │  3. Pull origin/main                 │
│            │ │  4. Push origin main                 │
│            │ │                                      │
│            │ │  [预览]  [执行]                       │
└────────────┴─┴──────────────────────────────────────┘
```

### 9.1 模板列表（左侧）

- 从 `~/.khaslana/workflows/` 目录加载 JSON5 文件
- 点击模板加载其定义和输入参数

### 9.2 工作流详情（右侧）

| 区域 | 说明 |
|------|------|
| 模板信息 | 名称、描述 |
| 输入参数 | 根据模板定义动态生成表单（文本输入、必填标记、默认值） |
| 步骤预览 | 展开显示每一步将执行的 Git 操作 |
| 操作按钮 | 预览（解析变量后展示实际命令）/ 执行 |

### 9.3 工作流步骤类型

| 步骤 | 说明 |
|------|------|
| Checkout | 切换到指定分支 |
| Fetch | 获取远端更新 |
| Pull | 拉取远端分支 |
| CreateBranch | 创建新分支 |
| Merge | 合并分支 |
| Push | 推送到远端 |
| GuardRemoteBranch | 检查远端分支存在性（存在/不存在时的策略） |
| EnsureClean | 确保工作区干净 |
| AssertBranch | 断言当前分支 |

### 9.4 执行状态

- 执行时显示进度条和当前步骤
- 每步完成/失败实时更新
- 执行完毕显示结果摘要

## 十、贮藏模式 (Stash)

预览贮藏内容和文件变更。

```
┌────────────┬─┬──────────────────────────────────────┐
│  贮藏文件   │↕│          Diff 视图                    │
│  列表      │ │                                      │
│  App.tsx   │ │  + stash content...                  │
│  config.js │ │  - original content...               │
└────────────┴─┴──────────────────────────────────────┘
```

| 交互 | 说明 |
|------|------|
| 点击文件 | 显示该文件在贮藏中的 Diff |
| 创建贮藏 | 工具栏"贮藏"按钮，弹出贮藏表单（可选消息） |
| 应用/弹出/丢弃 | 侧边栏贮藏区右键菜单 |

## 十一、浏览模式 (Browse)

只读浏览某分支或标签的文件内容，无需 checkout。

```
┌────────────┬─┬──────────────────────────────────────┐
│  文件树     │↕│  内容 / Diff 视图                     │
│            │ │                                      │
│ ▼ src/     │ │  // 文件只读内容                       │
│   App.tsx  │ │  import React from 'react';          │
│   util.ts  │ │                                      │
│ ▼ docs/    │ │  或                                  │
│   README.md│ │                                      │
│            │ │  // 与当前 HEAD 的差异                  │
└────────────┴─┴──────────────────────────────────────┘
```

### 11.1 文件树（左侧）

- 懒加载目录结构（点击目录展开子项）
- 支持两种子模式：
  - **树模式 (Tree)**：浏览分支的完整文件树
  - **对比模式 (Compare)**：仅显示与当前 HEAD 有差异的文件

### 11.2 内容/Diff 视图（右侧）

| 子模式 | 说明 |
|--------|------|
| Content | 只读显示文件内容（语法高亮） |
| Diff | 显示该文件与当前 HEAD 的差异 |

**AI Code Review**：在对比模式的 Diff 视图下方，可展开 AI 评审面板，对差异进行 AI 代码评审。

## 十三、AI 功能

### 13.1 AI 供应商设置弹窗

宽 560px，包含以下配置项：

| 字段 | 类型 | 说明 |
|------|------|------|
| 启用 AI | 开关 | 总开关，关闭后所有 AI 功能不可用 |
| 接口类型 | 只读显示 | 当前固定为 "Chat Completions"（OpenAI 兼容） |
| Base URL | 文本输入 | API 基础地址（如 `https://api.openai.com/v1`） |
| API Key | 文本输入 | 密钥（可选，本地模型如 Ollama 不需要） |
| Model | 文本输入 | 模型名称（如 `gpt-4o`、`deepseek-chat`） |

**辅助信息**：
- 提示 API Key 可选、明文保存
- 测试连接按钮：发送最小请求验证 API 可用性
- 保存/取消按钮

### 13.2 AI 生成 Commit Message

**入口**：工作区模式提交区域的"AI 生成"按钮

**流程**：
1. 系统收集所有已暂存文件的 Diff 文本（截断上限 6000 字符）
2. 构造中文 Conventional Commits 风格的 Prompt
3. 流式调用 Chat Completions API
4. 实时逐字填充提交信息输入框
5. 生成完毕后用户可编辑或直接提交

**触发条件**：
- 存在已暂存的文件
- AI 设置已配置且可用
- 当前没有正在生成的任务

### 13.3 AI Code Review

**入口**：浏览模式 → 对比模式 → Diff 视图下方的"AI 评审"面板

**流程**：
1. 系统收集当前文件与 HEAD 的 Diff 文本（截断上限 8000 字符）
2. 构造中文评审 Prompt（按严重问题/建议/风险点/优点分组）
3. 流式调用 Chat Completions API
4. 在评审面板中实时显示评审结果
5. 可折叠展开思考链 (Reasoning) 内容

**评审面板**：
- 位于 Diff 视图下方，可折叠
- 生成中显示加载动画
- 生成后显示正文 + 可选思考链
- 支持流式增量显示

### 13.4 AI 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| temperature | 0.3 | 生成随机性 |
| max_tokens | 800 | 最大输出 token 数 |
| request_timeout_secs | 60 | 请求超时时间 |
| 流式模式 | 开启 | commit/review 默认使用 SSE 流式 |

## 十七、核心交互流程

### 17.1 打开仓库

```
点击"打开仓库" → 系统文件对话框 → 选择目录 → 后台加载仓库
  → 加载成功: 侧边栏显示分支/远端、工作区显示变更
  → 加载失败: 显示错误反馈气泡
```

### 17.2 提交代码 (Commit)

```
工作区模式:
  1. 查看未暂存变更 → 点击 "+" 暂存文件
  2. 右侧查看暂存文件的 Diff
  3. 底部输入提交信息（或点击"AI 生成"）
  4. 点击"提交" → 成功后工作区清空
```

### 17.3 分支切换

```
侧边栏双击分支 → 后台执行 checkout
  → 成功: 刷新工作区变更和分支状态
  → 冲突: 自动切换到 Conflict 模式
```

### 17.4 拉取/推送

```
工具栏点击"拉取/推送" → 弹出远端分支操作对话框
  → 选择远端和分支 → 执行
  → 需要凭据: 弹出凭据输入对话框
  → 成功: 刷新状态 + 显示成功通知
```

### 17.5 冲突解决

```
合并/变基产生冲突 → 自动切入 Conflict 模式
  1. 左侧选择冲突文件
  2. 三栏工作台逐块选择 Ours/Theirs
  3. 全部解决后点击"提交解决"
  → 变基冲突: 底部额外显示"继续/跳过/中止"
```

### 17.6 AI 辅助工作流

```
AI Commit:
  1. 暂存文件 → 点击"AI 生成" → 流式生成提交信息 → 编辑/提交

AI Code Review:
  1. 浏览模式 → 切换到对比模式 → 选择文件
  2. Diff 视图下方展开"AI 评审"面板
  3. 流式生成评审结果 → 查看正文和思考链
```

### 17.7 工作流执行

```
切换到 Workflow 模式 → 选择模板 → 填写参数 → 预览步骤 → 执行
  → 每步实时显示进度
  → 步骤失败: 停止执行 + 显示错误
  → 全部完成: 显示结果摘要
```

## 二十、数据持久化

所有配置数据存储在 SQLite 数据库 (`khaslana.sqlite3`) 中：

| 数据表 | 内容 |
|--------|------|
| session_state | 上次打开的仓库路径、激活标签 |
| session_repositories | 仓库路径列表 |
| diff_encoding_preferences | 每个仓库的 diff 编码偏好 |
| network_proxy_settings | 全局代理设置 |
| remote_credential_bindings | 远端→凭据策略绑定 |
| credential_records | 凭据记录索引（密钥本体在系统 Keyring） |
| ai_provider_settings | AI 供应商配置 |

> **凭据安全**：密码/密钥等敏感信息存储在操作系统原生 Keyring 中，SQLite 仅存储索引和元数据。
