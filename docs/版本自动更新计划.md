# Khaslana 版本展示、CNB 默认更新源与自动更新计划

## Summary

- Khaslana 启动后默认从 **CNB 国内发布仓库**读取 `khaslana-update.json`，GitHub Release 只作为兜底源。
- Windows 构建仍在 GitHub Actions 完成；构建结束后 Actions 通过 CNB 访问令牌把 zip、sha256 和 manifest **git push 到 CNB 发布仓库**。
- `tencentcom/git-sync` 只用于可选的“源码/tag 同步到 CNB”，不负责上传 release zip。它支持 GitHub Actions 中同步到 CNB，并支持同步 tag；CNB 构建本身支持 `push` / `tag_push` 触发。
- 自动更新流程：检查 manifest → 比较版本 → 弹窗 → 下载 CNB zip → 校验 SHA-256 → 解压 staging → 启动更新器替换 exe → 重启应用。

参考：
- [CNB git-sync 插件](https://cnb.cool/cnb/plugins/tencentcom/git-sync)
- [CNB 触发规则](https://docs.cnb.cool/zh/build/trigger-rule.html)

## Release Topology

- GitHub 源码仓库保持现状：
  - `https://github.com/FuturePrayer/khaslana`
- 新增 CNB 发布仓库，专门放更新文件：
  - `https://cnb.cool/FuturePrayer/khaslana-release`
- CNB 发布仓库文件结构：

```text
khaslana-release/
  khaslana-update.json
  releases/
    v0.2.0/
      khaslana-v0.2.0-windows-x86_64.zip
      khaslana-v0.2.0-windows-x86_64.zip.sha256
    v0.3.0/
      khaslana-v0.3.0-windows-x86_64.zip
      khaslana-v0.3.0-windows-x86_64.zip.sha256
```

- 应用默认 manifest URL：

```text
https://cnb.cool/FuturePrayer/khaslana-release/-/raw/main/khaslana-update.json
```

- 应用 GitHub 兜底 manifest URL：

```text
https://github.com/FuturePrayer/khaslana/releases/latest/download/khaslana-update.json
```

- CNB zip URL 模式：

```text
https://cnb.cool/FuturePrayer/khaslana-release/-/raw/main/releases/v{version}/khaslana-v{version}-windows-x86_64.zip
```

- GitHub zip 兜底 URL 模式：

```text
https://github.com/FuturePrayer/khaslana/releases/download/v{version}/khaslana-v{version}-windows-x86_64.zip
```

## Manifest Contract

- 文件名：`khaslana-update.json`
- 版本号使用 Cargo 语义版本号，不带 `v`；tag 和文件名带 `v`。
- manifest 示例：

```json
{
  "schema": 1,
  "channel": "stable",
  "version": "0.2.0",
  "published_at": "2026-06-26T12:00:00Z",
  "notes": "版本更新说明摘要。",
  "platforms": {
    "windows-x86_64": {
      "archive_url": "https://cnb.cool/FuturePrayer/khaslana-release/-/raw/main/releases/v0.2.0/khaslana-v0.2.0-windows-x86_64.zip",
      "fallback_archive_url": "https://github.com/FuturePrayer/khaslana/releases/download/v0.2.0/khaslana-v0.2.0-windows-x86_64.zip",
      "sha256": "<64位小写十六进制>",
      "size": 12345678
    }
  }
}
```

- 应用只识别 `schema = 1` 和 `windows-x86_64`。
- `archive_url` 优先使用 CNB；下载失败再使用 `fallback_archive_url`。
- SHA-256 校验对象是整个 zip 文件，不是 exe。

## App Implementation

- 新增依赖：
  - `semver = "1"`：版本比较。
  - `sha2 = "0.10"`：SHA-256。
  - `zip`：解压更新包。
- 新增 `src/update.rs`：
  - 定义 `UpdateManifest`、`UpdatePlatformAsset`、`UpdatePreferences`、`UpdateCheckResult`、`UpdateDownloadResult`。
  - 提供 `current_version()`，返回 `env!("CARGO_PKG_VERSION")`。
  - 提供 `default_manifest_sources()`，顺序为 CNB → GitHub。
  - 提供 `check_for_update(preferences)`：拉取 manifest、解析、比较版本、跳过已忽略版本。
  - 提供 `download_update(asset)`：下载 zip 到配置目录下的 `updates/downloads/`。
  - 提供 `verify_sha256(path, expected)`。
  - 提供 `prepare_staging(zip)`：解压到 `updates/staging/v{version}/`，确认包含 `khaslana.exe` 和 `khaslana_updater.exe`。
- 新增 `src/bin/khaslana_updater.rs`：
  - 参数：`--pid`、`--target-exe`、`--new-exe`、`--new-updater`、`--backup-dir`、`--restart`。
  - 等待主进程退出，最多 30 秒。
  - 备份当前 `khaslana.exe` 和 `khaslana_updater.exe`。
  - 替换两个 exe。
  - 替换失败时恢复备份。
  - 成功后启动新的 `khaslana.exe`。
- 更新包 zip 内容：

```text
khaslana.exe
khaslana_updater.exe
LICENSE
README.md
```

- 如果当前安装目录不可写：
  - 不尝试 UAC 提权。
  - 弹窗提示「当前目录没有写入权限，请手动下载新版本」。
  - 提供打开 CNB 下载页或 GitHub Release 的按钮。

## Storage And Preferences

- `src/storage.rs`：
  - `SCHEMA_VERSION` 升级到 `2`。
  - 新增表：

```sql

    id INTEGER PRIMARY KEY CHECK (id = 1),

    skipped_version TEXT,
    updated_at INTEGER NOT NULL

```

- 新增方法：
  - `load_update_preferences() -> Result<UpdatePreferences>`
  - `save_update_preferences(&UpdatePreferences) -> Result<()>`

  - `skipped_version = None`

  - 用户点击「跳过此版本」后保存 `skipped_version = manifest.version`。

## GitHub Actions Release Workflow

- 新增 `.github/workflows/release.yml`。
- 触发：

```yaml
on:
  push:
    tags:
      - "v*"
```

- 必需 secrets：
  - `CNB_TOKEN`：可写 CNB 发布仓库的访问令牌。
- 可选 secrets：
  - `CNB_SOURCE_SYNC_TOKEN`：如果要同步源码仓库到 CNB，可复用 `git-sync`。
- job 步骤：
  - checkout，`fetch-depth: 0`。
  - 安装 Rust stable。
  - `cargo test`。
  - `cargo build --release --bin khaslana --bin khaslana_updater`。
  - 创建 `dist/package/`。
  - 复制 `khaslana.exe`、`khaslana_updater.exe`、`LICENSE`、`README.md`。
  - 打 zip：`khaslana-v{version}-windows-x86_64.zip`。
  - 生成 SHA-256：`khaslana-v{version}-windows-x86_64.zip.sha256`。
  - 生成 `khaslana-update.json`，其中 CNB URL 是主下载地址，GitHub URL 是 fallback。
  - 上传到 GitHub Release。
  - clone CNB 发布仓库，复制文件并 push。

- CNB 发布步骤示意：

```yaml
- name: Publish assets to CNB release repo
  shell: bash
  env:
    CNB_TOKEN: ${{ secrets.CNB_TOKEN }}
    VERSION_TAG: ${{ github.ref_name }}
  run: |
    VERSION="${VERSION_TAG#v}"
    ZIP="khaslana-v${VERSION}-windows-x86_64.zip"

    git clone "https://cnb:${CNB_TOKEN}@cnb.cool/FuturePrayer/khaslana-release.git" cnb-release
    mkdir -p "cnb-release/releases/v${VERSION}"

    cp "dist/${ZIP}" "cnb-release/releases/v${VERSION}/${ZIP}"
    cp "dist/${ZIP}.sha256" "cnb-release/releases/v${VERSION}/${ZIP}.sha256"
    cp "dist/khaslana-update.json" "cnb-release/khaslana-update.json"

    cd cnb-release
    git config user.name "github-actions"
    git config user.email "actions@github.com"
    git add .
    git commit -m "release: v${VERSION}" || exit 0
    git push
```

- 可选源码同步步骤：
  - 使用 `docker://tencentcom/git-sync`。
  - 作用只是把 GitHub 源码、分支和 tag 同步到 CNB，方便国内查看源码和触发 CNB 侧流程。
  - 不把它作为 release zip 上传机制。

## Optional CNB Pipeline

- 如果希望 CNB 仓库收到 tag 后有可视化记录，可在源码仓库添加 `.cnb.yml`：

```yaml
"$":
  tag_push:
    - stages:
        - name: release notice
          script: echo "Windows release assets are built by GitHub Actions and published to khaslana-release."
```

- 不建议让 CNB 从 GitHub Release 拉取 zip 再转存：
  - 境内网络访问 GitHub 不稳定。
  - Windows 构建已在 GitHub 完成，CNB 再拉 GitHub 会引入同一个网络问题。
  - GitHub Actions 直接 push 到 CNB 是最短链路。

## Test Plan

- `src/update.rs` 单元测试：
  - 当前版本低于 manifest 版本时返回可更新。
  - 当前版本等于或高于 manifest 版本时不提示。
  - skipped version 等于 manifest 版本时不提示。
  - skipped version 低于 manifest 版本时重新提示。
  - CNB 源排在 GitHub 源之前。
  - manifest schema 不支持时返回中文错误。
  - `windows-x86_64` 缺失时返回中文错误。
  - SHA-256 匹配通过，不匹配失败。
- `src/storage.rs` 单元测试：
  - 更新偏好默认值正确。
  - 自动检查开关 round trip。
  - 跳过版本 round trip。
- `src/bin/khaslana_updater.rs` 可测试逻辑：
  - 替换成功会生成备份。
  - 替换失败会恢复原 exe。
  - pid 等待超时会返回失败。
- CI 验证：
  - 对测试 tag `v0.0.99-test` 跑 release workflow。
  - 确认 GitHub Release 有 zip、sha256、manifest。
  - 确认 CNB 发布仓库出现同名文件。
  - 用浏览器或 `curl` 验证 CNB manifest URL 和 zip URL 可直接下载。
- 手工更新验证：
  - 本地运行旧版本。
  - 用本地或测试 CNB manifest 指向新 zip。
  - 验证弹窗、下载、校验、替换、重启。
  - 验证跳过版本后启动不再提示。

## Assumptions

- CNB 发布仓库使用公开仓库，更新 manifest 和 zip 不需要鉴权即可下载。
- CNB raw 直链采用 `/-/raw/main/...` 路径；实现前用一次 `curl` 确认返回 200。如果 CNB raw 不适合大文件直连，保持同一套 CI 产物，改为推送到腾讯云 COS/CDN。
- v1 自动更新只支持 Windows x86_64 portable exe。
- 旧版本没有更新器，因此用户需要手动安装第一个带自动更新能力的版本；之后版本可自动更新。
- 不做代码签名和增量更新；本轮只做 zip 完整包更新与 SHA-256 校验。
- 完成代码后同步更新 `README.md` 和 `AGENTS.md`，补充 CNB 发布仓库、release workflow、更新偏好和自动更新限制。
